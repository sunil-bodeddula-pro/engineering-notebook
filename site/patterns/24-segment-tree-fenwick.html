1. What is this pattern for?

A school keeps a running total of donations. With a single total per day (prefix sums), correcting one old entry means rewriting every later total. Instead, keep subtotals for blocks of days of size 1, 2, 4, 8…: a correction touches only the few blocks containing that day, and any range total is a sum of a few blocks. That is a Fenwick tree.

Three related tools:

  • Fenwick tree (binary indexed tree). Point update + prefix sum, both O(log n), in about ten lines. Also counts "how many values ≤ x seen so far" over compressed values.
  • Segment tree. A binary tree over ranges; each node stores a summary (sum, max, min, or a custom merge like longest run). Point/range updates and range queries in O(log n), plus "leftmost index with value ≥ x" by descending.
  • Sparse table. No updates, but range min/max in O(1) after O(n log n) preprocessing.

2. How it works (bisected)

  1. Name the query (sum, max, min, count of values in a range, a custom summary) and the update (point set, point add, none).
  2. Pick the structure: sums/counts with point updates → Fenwick; max/min or custom merges → segment tree; no updates and min/max → sparse table.
  3. Index it by position, or by value rank (coordinate compression) when you count values.
  4. Scan in the right order (often left-to-right or right-to-left) so the structure holds exactly the elements the query should see.

3. Seeing a problem: how to spot Segment / Fenwick Tree

Trigger words

  • "update" and "sum/min/max of range" in the same problem (a design class)
  • "count of smaller numbers after self", "reverse pairs", "inversions"
  • "number of subarrays with sum in [lower, upper]"
  • "after each query, the longest …" with single-element changes
  • "leftmost position with capacity ≥ x" with removals

Shape of the input

  • An array plus up to 10⁵ mixed updates and queries.
  • Pair counting with an order condition (i < j and a comparison of values).
  • Brute-force smell: rescanning a range per query, or O(n²) pair counting.
The one question to ask"Do I need range answers while the data keeps changing, or counts of earlier values in a value range?"

5. The templates, step by step (Python, TypeScript, Java)

When an array changes and you need range answers, prefix sums (page 1) are too slow to rebuild. Two templates fix that with O(log n) updates and queries. A the Fenwick tree (binary indexed tree) answers prefix sums using the lowest set bit of each index. B the iterative segment tree answers range max (or min, or sum) by climbing from two leaves towards the root.

Template A · Fenwick tree (point add, prefix sum)

The question it answersAdd to one position, and ask for the sum of positions 1..i, both many times.
What it keepstree[i] (1-indexed) = sum of the block of positions (i − lowbit(i), i], where lowbit(i) = i & -i.
When it checks for an answerprefix(i) adds blocks while stripping the lowest bit; add(i) updates every block that covers i by adding the lowest bit.
Use it whenRange sum with updates (LC 307), count of smaller numbers after self (LC 315), inversion counts, order statistics.
Not forRange max/min with updates (B), or a static array (plain prefix sums).
Memory hook: "Lowest bit off to read, lowest bit on to write"Each index i is a bucket covering the last lowbit(i) positions ending at i. To read 1..i, take bucket i, then jump left by its size (i − lowbit(i)), until 0. To add at i, every bucket that covers i must change: jump right by lowbit each time (i + lowbit(i)).

The story, mapped to the code. Indices start at 1; lowbit(6) = 2 (6 = 110₂), lowbit(4) = 4, lowbit(8) = 8.

The template. Two loops of the same shape, one going left, one going right. Positions are 1-based.

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def add(self, i, delta):
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i

    def prefix(self, i):
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= i & -i
        return total

    def range_sum(self, l, r):
        return self.prefix(r) - self.prefix(l - 1)
class Fenwick {
  n: number; tree: number[];
  constructor(n: number) {
    this.n = n;
    this.tree = new Array(n + 1).fill(0);
  }

  add(i: number, delta: number): void {
    for (; i <= this.n; i += i & -i) {
      this.tree[i] += delta;
    }
  }

  prefix(i: number): number {
    let total = 0;
    for (; i > 0; i -= i & -i) {
      total += this.tree[i];
    }
    return total;
  }

  rangeSum(l: number, r: number): number {
    return this.prefix(r) - this.prefix(l - 1);
  }
}

Template B · Iterative segment tree (point set, range max)

The question it answersSet one position, and ask for the max (or min, or sum) over l..r, both many times.
What it keepsAn array t of size 2 × size: leaves at size..2·size−1, each internal node = max of its two children.
When it checks for an answerA query walks two pointers up from the leaves, taking a node whenever it is a "lone" child at the edge of the range.
Use it whenRange max/min with updates, range sum with updates (Fenwick also works), skyline-style queries.
Not forRange updates (needs lazy propagation) or static arrays (a sparse table is O(1) per query).
Memory hook: "Leaves at the bottom; climb both ends and grab the edges"A knockout tournament bracket: each match winner (max) moves up. To ask who's best in a range of players, start at both ends of the range at the bottom and climb. Whenever an end is the outer child of its match, its winner is fully inside the range: take it and step inward.

The story, mapped to the code. Leaf i lives at t[size + i]; node k's children are 2k and 2k + 1.

The template. Half-open query [lo, hi + 1) on the leaves.

class MaxTree:
    def __init__(self, n):
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.t = [float("-inf")] * (2 * self.size)

    def set(self, i, val):
        i += self.size
        self.t[i] = val
        i //= 2
        while i:
            self.t[i] = max(self.t[2 * i], self.t[2 * i + 1])
            i //= 2

    def query(self, lo, hi):                  # inclusive lo..hi
        res = float("-inf")
        lo += self.size
        hi += self.size + 1
        while lo < hi:
            if lo & 1:
                res = max(res, self.t[lo])
                lo += 1
            if hi & 1:
                hi -= 1
                res = max(res, self.t[hi])
            lo //= 2
            hi //= 2
        return res
class MaxTree {
  size = 1; t: number[];
  constructor(n: number) {
    while (this.size < n) this.size *= 2;
    this.t = new Array(2 * this.size).fill(-Infinity);
  }

  set(i: number, val: number): void {
    i += this.size;
    this.t[i] = val;
    for (i >>= 1; i > 0; i >>= 1) {
      this.t[i] = Math.max(this.t[2 * i], this.t[2 * i + 1]);
    }
  }

  query(lo: number, hi: number): number {                // inclusive lo..hi
    let res = -Infinity;
    lo += this.size;
    hi += this.size + 1;
    while (lo < hi) {
      if (lo & 1) res = Math.max(res, this.t[lo++]);
      if (hi & 1) res = Math.max(res, this.t[--hi]);
      lo >>= 1;
      hi >>= 1;
    }
    return res;
  }
}

6. How to remember it forever

Memory hook: "Up by the low bit, down by the low bit"Fenwick add climbs with i += i & -i; prefix descends with i -= i & -i. Segment tree: leaves at size + i, parents at i // 2.
How this hook works: what “Up by the low bit, down by the low bit” means

What the slogan means, phrase by phrase

“the low bit”
i & -i, the lowest set bit of i. In a Fenwick tree it is the size of the block that tree[i] covers: tree[6] covers 2 positions (5–6), tree[8] covers 8 (1–8).
“Up by the low bit”
add climbs: i += i & -i reaches the next bigger block that also contains position i, and every block containing it gets updated.
“down by the low bit”
prefix descends: i -= i & -i jumps to the block just before the current one, adding non-overlapping blocks until 0.
“Segment tree: leaves at size + i, parents at i // 2”
The array version of a segment tree: children of node j are 2j and 2j + 1.

Why this picture fits the pattern: These trees exist for range questions with updates. Plain prefix sums answer fast but update slowly. Blocks of power-of-two size make both take O(log n), and the low bit is how you move between blocks.

Watch it on numbers

A Fenwick tree over 8 positions.

  1. add(3, …): 3 → 3 + 1 = 4 → 4 + 4 = 8 → 16 is past the end, stop. Blocks 3, 4 and 8 contain position 3.
  2. prefix(7): take tree[7] (position 7), go 7 − 1 = 6, take tree[6] (5–6), go 6 − 2 = 4, take tree[4] (1–4), go 4 − 4 = 0, stop.
  3. Three blocks cover 1–7 exactly, with no overlap and no gap. Both operations are O(log n).

The trap it saves you from

Using index 0: 0 & -0 is 0, so the loop never moves (an infinite loop). Fenwick positions are 1-based. Values up to 10⁹ must be compressed to ranks before they can be positions.

Hint 1

Prefix sums are fast to query but slow to update. Can you balance both?

Hint 2

Use a Fenwick tree or segment tree.

From brute force to the pattern: Recomputing sums per query is O(n); the Fenwick tree makes both operations O(log n).

Spot it: Prefix sums make queries O(1) but updates O(n). A Fenwick (binary indexed) tree stores partial sums over blocks sized by the lowest set bit, so both operations take O(log n).

Why not another pattern? A plain prefix-sum array needs an O(n) rebuild per update; recomputing sums per query is O(n).

Approach:

  1. tree is 1-indexed; add(i, delta): while i ≤ n: tree[i] += delta, i += i & −i.
  2. prefix(i): while i > 0: sum tree[i], i −= i & −i.
  3. update: add the difference; sumRange(l, r) = prefix(r + 1) − prefix(l).
class NumArray:
    def __init__(self, nums: List[int]):
        self.n = len(nums)
        self.nums = nums[:]

Hint 1

Process from the right so that everything seen so far is to the right.

Hint 2

You need "how many seen values are smaller than x" quickly: a Fenwick tree over ranks.

From brute force to the pattern: All pairs: O(n²). Fenwick tree (or merge sort counting): O(n log n).

Spot it: Walk from the right, inserting values into a Fenwick tree indexed by rank (coordinate compression). Before inserting x, the prefix sum up to rank(x) − 1 is the number of smaller values already seen, i.e. to its right.

Why not another pattern? Checking all pairs is O(n²).

  2. From right to left: counts[i] = prefix(rank[x] − 1); then add(rank[x], 1).

Hint 1

Let dp[v] be the longest valid subsequence ending with value v.

Hint 2

From brute force to the pattern: The pairwise DP is O(n²); a value-indexed segment tree is O(n log V).

Spot it: LIS ending at value v extends any subsequence ending at a value in [v − k, v − 1]. That's a range-max query plus a point update over values → a segment tree indexed by value.

Why not another pattern? The O(n²) LIS DP is too slow for n = 10⁵; patience sorting can't express the ≤ k gap rule.

Approach:

  1. Segment tree over values 1..max.
  2. For each x: cur = 1 + max(query(x − k, x − 1)); update(x, cur).
  3. Answer: the maximum cur.

8. Common mistakes

0-based vs 1-based Fenwick indicesIndex 0 makes i & -i equal 0 and the update loop never ends. Shift positions by one.
Updating with the new value instead of the differenceA Fenwick tree adds deltas: update(i, val) must add val − old and remember the new value.
Inserting before queryingIn "count earlier smaller values", query first, then insert the current value, or it counts itself.
Forgetting coordinate compressionIndexing a tree by raw values up to 10⁹ (or negative values) is impossible; map values to ranks.
Segment tree sizeA recursive tree needs about 4n nodes; the iterative one needs 2 · size with size a power of two ≥ n.

9. Self-check quiz

Point updates and range-sum queries, 10⁵ of each. Simplest structure?

Prefix sums need O(n) per update; sparse tables don't support updates; Fenwick does both in O(log n).

Scanning from the right means the tree holds exactly the elements after x.

Each query changes one character; report the longest run of equal characters. Which structure?

The summary (prefix run, suffix run, best run) is mergeable but not a sum, so a segment tree fits.

A fixed array, 10⁵ range-maximum queries, no updates. Fastest per query?

  2. For each P[j] in order: count compressed prefixes with value in the window (two bisects on the sorted values, two prefix queries); then insert P[j].

Hint 2

From brute force to the pattern: Scanning obstacles per query is O(q²); a max segment tree over gaps makes queries O(log X).

Spot it: The answer is whether the largest free gap inside [0, x] is ≥ sz. Keep the obstacles sorted (with 0 as a virtual obstacle); store each obstacle's gap to its predecessor at its position in a max segment tree. A query is the max over obstacles ≤ x, plus the tail gap x − last.

  1. obstacles = [0] (sorted); segment tree over positions 0..max x.
  2. Insert x between p and q: gap[x] = x − p, gap[q] = q − x (if q exists).

        while (1 << j) <= n:
            half = 1 << (j - 1)
            hi_t.append([max(hi_t[-1][i], hi_t[-1][i + half]) for i in range(n - (1 << j) + 1)])

            low = min(lo_t[j][l], lo_t[j][r - (1 << j) + 1])

        return total

// ---- helper: a small binary heap (TypeScript has no built-in priority queue) ----
// `less(a, b)` decides which item comes out first. The player doesn't step inside it.
class Heap<T> {
    private items: T[] = [];
    private less: (a: T, b: T) => boolean;

    constructor(less: (a: T, b: T) => boolean) {
        this.less = less;
    }

    get size(): number {
        return this.items.length;
    }

    peek(): T {
        return this.items[0];
    }

    push(x: T): void {
        const a = this.items;
        a.push(x);
        let i = a.length - 1;
        while (i > 0) {
            const parent = (i - 1) >> 1;
            if (!this.less(a[i], a[parent])) {
                break;
            }
            [a[i], a[parent]] = [a[parent], a[i]];
            i = parent;
        }
    }

    pop(): T {
        const a = this.items;
        const top = a[0];
        const last = a.pop()!;
        if (a.length > 0) {
            a[0] = last;
            let i = 0;
            while (true) {
                const l = 2 * i + 1;
                const r = l + 1;
                let m = i;
                if (l < a.length && this.less(a[l], a[m])) {
                    m = l;
                }
                if (r < a.length && this.less(a[r], a[m])) {
                    m = r;
                }
                if (m === i) {
                    break;
                }
                [a[i], a[m]] = [a[m], a[i]];
                i = m;
            }
        }
        return top;
    }
}

class Solution:
    def countGoodSubseq(self, nums: List[int], p: int, queries: List[List[int]]) -> int:
        n = len(nums)
        size = 1
        while size < n:
            size *= 2
        tree = [0] * (2 * size)  # gcd of multiples of p; 0 is the identity

        def put(i, value):
            i += size
            tree[i] = value if value % p == 0 else 0
            i //= 2
            while i:
                tree[i] = gcd(tree[2 * i], tree[2 * i + 1])
                i //= 2

        multiples = 0
        for i, v in enumerate(nums):
            put(i, v)
            multiples += v % p == 0
        good = 0
        for idx, val in queries:
            multiples += (val % p == 0) - (nums[idx] % p == 0)
            nums[idx] = val
            put(idx, val)
            if tree[1] != p:
                continue  # even all multiples together don't have gcd exactly p
            if multiples < n or n >= 8:
                good += 1  # all multiples form a proper subsequence (or a small proper subset exists)
                continue
            for skip in range(n):  # tiny n: try leaving one element out
                g = 0
                for j in range(n):
                    if j != skip:
                        g = gcd(g, nums[j])
                if g == p:
                    good += 1
                    break
        return good

        put(i, v);
        multiples += v % p === 0 ? 1 : 0;
    });
    let good = 0;
    for (const [idx, val] of queries) {
        multiples += (val % p === 0 ? 1 : 0) - (nums[idx] % p === 0 ? 1 : 0);
        nums[idx] = val;
        put(idx, val);
        if (tree[1] !== p) {
            continue;  // even all multiples together don't have gcd exactly p
        }
        if (multiples < n || n >= 8) {
            good += 1;  // all multiples form a proper subsequence (or a small proper subset exists)
            continue;
        }
        for (let skip = 0; skip < n; skip++) {  // tiny n: try leaving one element out
            let g = 0;
            for (let j = 0; j < n; j++) {
                if (j !== skip) {
                    g = gcd(g, nums[j]);
                }
            }
            if (g === p) {
                good += 1;
                break;
            }
        }
    }
    return good;
}
class Solution {
    private int size;
    private int p;
    private int[] tree;  // gcd of multiples of p; 0 is the identity

    public int countGoodSubseq(int[] nums, int p, int[][] queries) {
        this.p = p;
        int n = nums.length;
        size = 1;
        while (size < n) {
            size *= 2;
        }
        tree = new int[2 * size];
        int multiples = 0;
        for (int i = 0; i < n; i++) {
            put(i, nums[i]);
            multiples += nums[i] % p == 0 ? 1 : 0;
        }
        int good = 0;
        for (int[] q : queries) {
            int idx = q[0], val = q[1];
            multiples += (val % p == 0 ? 1 : 0) - (nums[idx] % p == 0 ? 1 : 0);
            nums[idx] = val;
            put(idx, val);
            if (tree[1] != p) {
                continue;  // even all multiples together don't have gcd exactly p
            }
            if (multiples < n || n >= 8) {
                good += 1;  // all multiples form a proper subsequence (or a small proper subset exists)
                continue;
            }
            for (int skip = 0; skip < n; skip++) {  // tiny n: try leaving one element out
                int g = 0;
                for (int j = 0; j < n; j++) {
                    if (j != skip) {
                        g = gcd(g, nums[j]);
                    }
                }
                if (g == p) {
                    good += 1;
                    break;
                }
            }
        }
        return good;
    }

    private void put(int i, int value) {
        i += size;
        tree[i] = value % p == 0 ? value : 0;
        i /= 2;
        while (i > 0) {
            tree[i] = gcd(tree[2 * i], tree[2 * i + 1]);
            i /= 2;
        }
    }

    private int gcd(int a, int b) {
        return b == 0 ? a : gcd(b, a % b);
    }
}

What the code is doing, line by line:

  1. A subsequence with gcd exactly p uses only multiples of p; adding more multiples can only lower the gcd toward their total gcd, so the total gcd must be p.
  2. If some element isn't a multiple, "all multiples" is already shorter than n.
  3. If all are multiples with gcd p, the values divided by p have gcd 1; one element plus one counterexample per prime factor (at most 6) gives a gcd-1 subset of at most 7 elements, so n ≥ 8 always works.
