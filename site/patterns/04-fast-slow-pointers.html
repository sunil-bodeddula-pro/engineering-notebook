Fast & Slow Pointers

Send two runners down the same path, one twice as fast as the other. Where and whether they meet tells you about the shape of the path (its middle, whether it loops, and where the loop begins) using O(1) memory.

1. What is this pattern for?

A tortoise and a hare race on a track. If the track is a straight road, the hare simply reaches the end first, and at that moment the tortoise is exactly halfway. If the track is a circular running loop, the hare eventually comes around from behind and laps the tortoise. They can only meet if there's a loop.

This pattern (also called Floyd's tortoise and hare) works on anything where "go to the next thing" is well defined: a linked list (node.next), an array used as a map (i → nums[i]), or a function (n → sum of squares of digits). It answers:

  • Is there a cycle? (they meet ⇔ yes)
  • Where does the cycle start? (a second, equal-speed walk)
  • Where's the middle? (when fast hits the end, slow is in the middle). That's the first step of many list problems: palindrome check, reorder, split for merge sort.

The alternative is a hash set of visited nodes, which needs O(n) memory. Fast & slow uses O(1).

2. How it works (bisected)

  1. Start both at the head. slow = head and fast = head.
  2. Move at different speeds. Each round: slow = slow.next (1 step), fast = fast.next.next (2 steps). Guard with while fast and fast.next so fast never steps off the end.
  3. No cycle → fast falls off. When the loop ends, fast has walked twice as far, so slow is at the middle (the second middle for even lengths).
  4. Cycle → they meet. Inside the loop, the gap between them shrinks by exactly 1 every round, so fast can't jump over slow. They must land on the same node within one lap.
  5. Find the entrance. Put one pointer back at the head and move both 1 step at a time. They meet exactly at the cycle's first node. (Why: if the tail has length a and they met b steps into a loop of length L, then 2(a+b) = a+b+kL, so a = kL − b: walking a steps from the meeting point lands on the entrance.)

3. Seeing a problem: how to spot Fast & Slow

Trigger words

  • "linked list" + "cycle", "loop", "where the cycle begins"
  • "middle of the linked list", "second half", "palindrome linked list", "reorder"
  • "find the duplicate" with values in 1..n, "without modifying the array", "O(1) space"
  • "repeat the process… does it end in 1 or loop forever?" (Happy Number)
  • "circular array", "jump forward/backward by nums[i]"

Shape of the input

  • A next-function: node.next, nums[i], or a computed successor.
  • You can only walk forward (singly linked), and you don't know the length.
  • Brute-force smell: "store every visited node in a set" or "count the length first, then walk again". The interviewer then asks for O(1) space or one pass.
The one question to ask"Is there a 'next' rule I keep following, and do I care whether it loops or where its middle is?" If yes, race two pointers at speeds 1 and 2.

4. When to use it, and when not to

Use Fast & Slow when…Prefer something else when…
Detecting a cycle / its start in O(1) spaceMemory isn't a concern and you want simple code: a set() of visited nodes
Finding the middle of a singly linked list in one passYou have random access (an array): just use n // 2
Splitting a list before reversing half (palindrome, reorder)The task is to reverse a list or parts of it: that's LinkedList Reversal (often used right after this one)
Duplicate in 1..n without modifying the arrayThe pointers walk toward each other on a sorted array: that's Two Pointers
Cycle in an implicit "next" functionCycles in a general graph (many edges per node): use DFS with colours, or topological sort

Cost: O(n) time. Fast covers at most ~2n steps before falling off or meeting, and phase 2 is at most n more. O(1) extra space.

5. The templates, step by step (Python, TypeScript, Java)

Fast & Slow Pointers has three templates built on one move: a tortoise takes one step while a hare takes two. A uses the fact that the hare covers twice the distance (so the tortoise ends halfway). B uses the fact that a faster runner on a loop always laps a slower one. C adds a second phase that finds where the loop starts.

6. How to remember it forever

Memory hook: "Hare laps tortoise"A straight road: the hare finishes while the tortoise is at halftime. A running track: the hare laps the tortoise. Then both stroll from (start, meeting point) and bump into each other at the gate.
How this hook works: what “Hare laps tortoise” means

What the slogan means, phrase by phrase

“Hare”
The fast pointer: fast = fast.next.next, two nodes per round.
“tortoise”
The slow pointer: slow = slow.next, one node per round.
“A straight road: the hare finishes while the tortoise is at halftime”
If the list ends, fast reaches the end when slow has gone half as far: slow is the middle.
“A running track: the hare laps the tortoise”
If the list loops, the hare can't fall off the end. It gains one node per round and eventually catches the tortoise from behind: slow is fast means there is a cycle.
“both stroll … and bump into each other at the gate”
To find where the loop starts, put one pointer back at the head, leave one at the meeting point, and move both one step at a time. They meet at the loop's entrance (the "gate").

Why this picture fits the pattern: Linked lists have no length and no indexes. Two runners at different speeds learn about the shape of the list (its middle, whether it loops, where the loop starts) in one pass with O(1) memory.

The story → the code

In the storyIn the code
Tortoise / hareslow = slow.next / fast = fast.next.next
The road endsfast is None or fast.next is None
Hare laps tortoiseslow is fast
Stroll to the gateslow = head, then both move 1 step until slow is fast

Watch it on numbers

A list 1 → 2 → 3 → 4 → 5, where 5 points back to 3. The gate is node 3.

  1. Start: both on 1. Round 1: tortoise 2, hare 3. Round 2: tortoise 3, hare 5.
  2. Round 3: tortoise 4, hare 5 → 3 → 4. Same node: the hare lapped the tortoise, so there is a loop.
  3. Stroll: one walker from the head (1), one from the meeting point (4). Next: 2 and 5. Next: 3 and 3. They meet at the gate.
  4. Why it works: the tail is 2 steps long, and the meeting point is 1 step past the gate on a 3-node loop. Walking 2 more steps from there wraps round to the gate, exactly as 2 steps from the head do.

The trap it saves you from

Jumping two steps without checking both fast and fast.next (a crash on even-length lists), or comparing slow.val == fast.val instead of slow is fast (different nodes can hold equal values).

It still works when…

Happy Number: the "track" is the sequence of digit-square sums. If it loops without reaching 1, the hare laps the tortoise. Find the Duplicate Number: treat i → nums[i] as a list, and the gate is the duplicate.

Picture

The Greek letter ρ (rho): a tail leading into a loop. The meeting happens on the loop; the gate is where the tail joins it.

Chant

"One step, two steps. Meet? Loop. Reset one, walk both, meet at the gate."

Guard rule

"Check fast and fast.next." The fast runner looks two steps ahead before jumping.

Hint 1

Values are in 1..n and there are n + 1 of them. Treat i → nums[i] as a "next" pointer.

Hint 2

The duplicate value has two arrows pointing at it: it's the entrance of a cycle. Use Floyd's two phases.

From brute force to the pattern: A set of seen values is O(n) space; sorting modifies the array; checking every pair is O(n²). Following i → nums[i] turns the array into a linked list with a cycle whose entrance is the duplicate, which Floyd finds in O(n) time and O(1) space without changing anything.

Spot it: values are valid indices, so treat i → nums[i] as a "next" pointer. Index 0 is never a target (values ≥ 1), so it's the head of a tail. Two indices point at the duplicate value, so that node has two arrows coming in: the entrance of a cycle. "Duplicate + O(1) space + read-only" means Floyd.

Key insight: the duplicate is the cycle start. Run template C with slow = nums[slow] and fast = nums[nums[fast]].

Approach:

  1. Treat each index i as a node whose next is nums[i], starting from index 0.
  2. Phase 1: slow = nums[slow], fast = nums[nums[fast]] until they're equal.
  3. Phase 2: reset slow to the start (nums[0]) and keep fast at the meeting point.
  4. Move both one hop at a time. Where they meet is the cycle entrance, which is the duplicate.
from typing import List

class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # Treat every index as a "node" and nums[index] as its "next" arrow.
        # Index 0 is the head (no value is 0, so nothing points back at it).
        # One hop from index 0 lands on nums[0]; both runners start there.
        slow = nums[0]
        fast = nums[0]

        # Phase 1: slow hops once, fast hops twice, until they land together.
        while True:
            slow = nums[slow]          # slow: 1 hop
            fast = nums[fast]          # fast: first hop
            fast = nums[fast]          # fast: second hop (same as nums[nums[fast]])
            if slow == fast:
                break                  # they met somewhere inside the loop

        # Phase 2: put slow back at the start, leave fast at the meeting point.
        slow = nums[0]
        # Both now hop ONE step at a time; they meet at the loop entrance.
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]

        # Two different indices point at the entrance, so it is the duplicate.
        return slow

What the code is doing, line by line:

  1. slow = nums[0] and fast = nums[0]: index 0 is the "head" of our hidden linked list (no value is 0, so no arrow ever points back to index 0). Its arrow leads to nums[0], so both runners start there.
  2. while True: we don't know how many rounds phase 1 needs, so we loop "forever" and leave with break.
  3. Inside the loop, slow = nums[slow] follows one arrow. fast = nums[fast] written twice follows two arrows. That is the same as nums[nums[fast]], split into two easy lines.
  4. if slow == fast: break: they are on the same index, so they met inside the loop. We compare after moving because they start out equal.
  5. Phase 2: slow = nums[0] sends slow back to the start while fast stays at the meeting point. while slow != fast: moves both one arrow at a time.
  6. return slow: where they meet is the entrance of the loop. Two different indices point to it, so that value appears twice: it is the duplicate.

Spot it: "circular" + "jump by nums[i]" defines a next function (i + nums[i]) % n. Detect a cycle with fast/slow, with extra rules.

Key insight: abort a run as soon as fast would step onto a node of the opposite direction or a self-loop (next(j) == j). Afterwards, zero out the path you walked so each index is explored once overall: O(n).

Approach:

  1. For each unvisited start i, remember its direction (forward if nums[i] > 0).
  2. Run slow/fast with next(i) = (i + nums[i]) % n, but only while fast's next two steps keep that direction and aren't self-loops.
  3. If slow == fast, a valid cycle exists → True.
  4. Otherwise zero out every index on this same-direction path so it's never explored again.
  5. If no start finds a cycle, return False.
class Solution:
    def next_index(self, nums: List[int], index: int) -> int:
        # Jump nums[index] steps. "% size" wraps around the circle;
        # in Python the result of % is always between 0 and size - 1,
        # even when the jump is negative.
        size = len(nums)
        return (index + nums[index]) % size

    def is_legal_step(self, nums: List[int], index: int, forward: bool) -> bool:
        # 1) 0 means "already explored, leads nowhere": not legal.
        if nums[index] == 0:
            return False
        # 2) It must move in the same direction as the run we started.
        moves_forward = nums[index] > 0
        if moves_forward != forward:
            return False
        # 3) Jumping back onto itself is a loop of length 1: not allowed.
        if self.next_index(nums, index) == index:
            return False
        return True

    def circularArrayLoop(self, nums: List[int]) -> bool:
        size = len(nums)
        for start in range(size):
            # Skip positions an earlier run already proved useless.
            if nums[start] == 0:
                continue
            # Remember this run's direction (True = forward, False = backward).
            forward = nums[start] > 0

            # Floyd: slow makes 1 jump per round, fast makes 2 jumps.
            slow = start
            fast = start
            while True:
                # fast may only jump if its current spot is legal ...
                if not self.is_legal_step(nums, fast, forward):
                    break
                fast_after_one_jump = self.next_index(nums, fast)
                # ... and the spot after its first jump is legal too.
                if not self.is_legal_step(nums, fast_after_one_jump, forward):
                    break
                slow = self.next_index(nums, slow)
                fast = self.next_index(nums, fast_after_one_jump)
                if slow == fast:
                    return True                   # met inside a valid loop

            # No loop from this start. Zero out the same-direction path we walked
            # so that no later start walks it again (this keeps the total O(n)).
            index = start
            while nums[index] != 0:
                moves_forward = nums[index] > 0
                if moves_forward != forward:
                    break                         # the path turned around: stop
                following = self.next_index(nums, index)   # compute BEFORE zeroing
                nums[index] = 0
                index = following
        return False

        # which makes slow stop on the last node of the first half.

function sortList(head: ListNode | null): ListNode | null {

    if (head === null || head.next === null) {
        return head;

    // Find the END of the first half. fast starts one node ahead,
    // which makes slow stop on the last node of the first half.
    let slow: ListNode = head;

        slow = slow.next!;
        fast = fast.next.next;

    slow.next = null;

    // Sort each half (recursion), then merge the two sorted halves.

    const sortedSecond = sortList(secondHalf);

Problem: In a list of even length n, node i and node n−1−i are twins. Return the largest twin sum.

Solve it on LeetCode ↗

Example 1
Input: head = [5,4,2,1]
Output: 6
Explanation: Nodes 0 and 1 are the twins of nodes 3 and 2, respectively. All have twin sum = 6. There are no other nodes with twins in the linked list. Thus, the maximum twin sum of the linked list is 6.
Example 2
Input: head = [4,2,2,3]
Output: 7
Explanation: The nodes with twins present in this linked list are: - Node 0 is the twin of node 3 having a twin sum of 4 + 3 = 7. - Node 1 is the twin of node 2 having a twin sum of 2 + 2 = 4. Thus, the maximum twin sum of the linked list is max(7, 4) = 7.

Constraints: The number of nodes in the list is an even integer in the range [2, 10⁵]. · 1 ≤ Node.val ≤ 10⁵

Hint 1

Node i pairs with node n − 1 − i: the first half pairs with the second half read backwards.

Hint 2

Find the middle, reverse the second half, then walk both halves together summing pairs.

From brute force to the pattern: Copying values to an array and summing a[i] + a[n − 1 − i] is O(n) space. Middle + reverse + walk does it in place with O(1) space.

Spot it: Pair the first half with the second half read backwards → middle (fast/slow) + reverse the second half.

Approach:

  1. Fast/slow: slow lands on the first node of the second half.
  2. Reverse the second half.
  3. Walk from head and from the reversed half together, adding twin values.
  4. Return the maximum sum.

        slow = head
        fast = head

            slow = slow.next
            fast = fast.next.next

        # Step 2: reverse the second half.
        previous_node = None
        current_node = slow

        # the reversed half, which means "backwards" through the original list.

            if twin_sum > best_sum:
                best_sum = twin_sum               # a new best pair
            left = left.next
            right = right.next
        return best_sum

Medium 19. Remove Nth Node From End of List Google Meta Amazon Microsoft Linked List

Problem: Remove the n-th node from the end of the linked list and return its head, in one pass.

Solve it on LeetCode ↗ · Video walkthrough ↗

Example 1
Input: head = [1,2,3,4,5], n = 2
Output: [1,2,3,5]
Example 2
Input: head = [1], n = 1
Output: []

Constraints: The number of nodes in the list is sz. · 1 ≤ sz ≤ 30 · 0 ≤ Node.val ≤ 100 · 1 ≤ n ≤ sz

Hint 1

If fast starts n nodes ahead of slow, where is slow when fast falls off the end?

Hint 2

Start slow at a dummy node before the head so it stops right before the node to delete.

From brute force to the pattern: Counting the length, then walking to position length − n, is two passes. A fixed gap between two pointers finds the node in one pass; the dummy node handles deleting the head.

Spot it: "N-th from the end" without knowing the length → two runners. Here they move at the same speed but with a head start of n, so when the leader falls off the end, the follower stands just before the target.

Key insight: A dummy node before head means the node before the target always exists, even when the target is the head itself (n equal to the length).

Approach:

  1. Put a dummy node in front of head.
  2. Move fast forward n nodes from head.
  3. Start slow at dummy, then move both one step at a time until fast is None.
  4. slow is now just before the node to delete: set slow.next = slow.next.next.
  5. Return dummy.next (the head may have changed).
class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        # a fake node before head, so removing the head needs no special case
        dummy = ListNode(0, head)
        fast = head
        # give fast a head start of n nodes
        for _ in range(n):
            fast = fast.next
        slow = dummy
        # move together; the gap between them stays n
        while fast is not None:
            fast = fast.next
            slow = slow.next
        # slow is right before the node to remove: skip over it
        slow.next = slow.next.next
        return dummy.next

Problem: Values are in 1..n and each appears once or twice. Return all values that appear twice, in O(n) time and O(1) extra space.

Solve it on LeetCode ↗

Example 1
Input: nums = [4,3,2,7,8,2,3,1]
Output: [2,3]
Example 2
Input: nums = [1,1,2]
Output: [1]

Constraints: n == nums.length · 1 ≤ n ≤ 10⁵ · 1 ≤ nums[i] ≤ n · Each element in nums appears once or twice.

Hint 1

Values are between 1 and n. Could the array itself remember which values you have seen?

Hint 2

Use the sign of nums[x − 1] as a "seen x" flag.

From brute force to the pattern: A hash set finds duplicates in O(n) but uses O(n) space; sorting changes the order and costs O(n log n). Using the sign at each value's home index as a marker gives O(n) time with O(1) extra space.

Spot it: Values are valid indices (x → x − 1), the same structure Fast & Slow uses in Find the Duplicate Number. Here we use each value's home index as a marker: make it negative the first time; finding it already negative means a duplicate.

Why not another pattern? A set or counter is O(n) extra space; sorting is O(n log n). Floyd's cycle finding returns only one duplicate, not all of them.

Approach:

  1. For each x in nums, look at home = abs(x) − 1 (use abs because earlier steps may have negated x).
  2. If nums[home] is already negative, abs(x) was seen before: record it.
  3. Otherwise negate nums[home] to mark abs(x) as seen.

                duplicates.append(value)  # its marker is set: seen before
            else:

Hard 41. First Missing Positive Google Meta Amazon Microsoft Netflix Array

Problem: Return the smallest positive integer that is not in nums, in O(n) time and O(1) extra space.

Solve it on LeetCode ↗

Example 1
Input: nums = [1,2,0]
Output: 3
Explanation: The numbers in the range [1,2] are all in the array.
Example 2
Input: nums = [3,4,-1,1]
Output: 2
Explanation: 1 is in the array but 2 is missing.

Constraints: 1 ≤ nums.length ≤ 10⁵ · -2³¹ ≤ nums[i] ≤ 2³¹ - 1

Hint 1

The answer is between 1 and n + 1. Can the array's own indices act as a "seen" table?

Hint 2

Try to put value v at index v − 1 by swapping; afterwards, scan for the first index that doesn't hold i + 1.

From brute force to the pattern: Checking 1, 2, 3, … with a linear search each time is O(n²); a set is O(n) time but O(n) space; sorting is O(n log n). Because the answer lies in 1..n + 1, each value can be swapped into its own index, and one more scan finds the gap: O(n) time, O(1) space.

Spot it: The answer is always in 1..n + 1 (n numbers can cover at most 1..n). So the array itself can be used as the "seen" table: index v − 1 is the home of value v. Following i → nums[i] − 1 and swapping values home is the cyclic-indices trick, a cousin of fast & slow on i → nums[i] (Find the Duplicate Number).

Why not another pattern? A hash set gives O(n) time but O(n) space, and sorting is O(n log n); both break the constraints. Binary search doesn't apply because the input isn't sorted.

Key insight: Swap each value v in 1..n into position v − 1 until every position holds its own value or a value that has no home (≤ 0, > n, or a duplicate). Then the first index i with nums[i] != i + 1 gives the answer i + 1. Each swap puts one value home for good, so there are at most n swaps in total.

Approach:

  1. For each index i: while nums[i] is in 1..n and its home nums[i] − 1 doesn't already hold the same value, swap it home.
  2. Values outside 1..n, and duplicates, are left where they are.
  3. Scan again: the first index i with nums[i] != i + 1 means i + 1 is missing.
  4. If every position is correct, the answer is n + 1.
class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        n = len(nums)
        for i in range(n):
            # keep sending nums[i] to its home (index value - 1) while that's possible
            while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
                home = nums[i] - 1  # where this value belongs
                nums[i], nums[home] = nums[home], nums[i]  # move it home
        for i in range(n):
            if nums[i] != i + 1:
                return i + 1  # the first position without its own value
        return n + 1  # 1..n are all present
