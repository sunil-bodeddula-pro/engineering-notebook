1. What is this pattern for?

Picture a conga line where each dancer holds the shoulder of the person in front. To make the line face the other way, you walk down it and tell each dancer, one by one, to let go and grab the person who was behind them instead. You only ever need to remember three people: the one you just turned around (prev_node), the one you're turning now (current), and the next one in line (next_node), so you don't lose the rest of the line when current lets go.

A singly linked list is a chain of nodes where each node knows only its next. You can't index into it or walk backwards. The in-place reversal pattern rewires the next pointers so the chain points the other way, in O(n) time and O(1) extra space (no copying into an array).

It's the building block for: reversing the whole list, reversing positions left..right, reversing every group of k, swapping pairs, and "compare the first half with the reversed second half" problems (palindrome, twin sums, reorder).

2. How it works (bisected)

  1. Set up. prev_node = None (the new tail will point at nothing), current = head.
  2. Save. next_node = current.next. Do this first, because the next line destroys your only link to the rest of the list.
  3. Flip. current.next = prev_node. The arrow now points backwards.
  4. Advance both. prev_node = current, then current = next_node. Repeat steps 2–4 until current is None.
  5. Return prev_node: it's the old tail, now the new head.
  6. Level up: reverse just a part. Use a dummy node before the head so "the node before the part" always exists (even when the part starts at the head). Remember the node just before the part and the part's first node (it'll become the part's tail), reverse the part, then stitch both ends back.

Naming note: the code on this page uses the long names prev_node, current and next_node. The animations below have little room for labels, so they shorten them to prev, cur and nxt. They are the same three pointers.

3. Seeing a problem: how to spot In-place Reversal

Trigger words

  • "reverse the linked list", "reverse from position left to right"
  • "reverse nodes in k-group", "swap every two adjacent nodes"
  • "in place", "O(1) extra memory", "do not modify the values, only the nodes"
  • "palindrome linked list", "twin sum", "reorder list", "add two numbers II" (when the digits are stored in an inconvenient order)

Shape of the input

  • A singly linked list (ListNode with val and next).
  • You need to traverse it in the opposite order, or reorder blocks of nodes.
  • Brute-force smell: "copy all values into a Python list, reverse/re-arrange, write them back". That's O(n) extra space, and often forbidden ("don't change values").
The one question to ask"Would this be easy if (part of) the list pointed the other way?" If yes, flip it in place with prev_node / current / next_node.

5. The templates, step by step (Python, TypeScript, Java)

In-place reversal has two templates. A flips every arrow in the list using three pointers. B reverses only positions left..right: a dummy node stands in front, and nodes are moved one at a time to the front of the section ("head insertion"). Both change arrows, never values, and both use O(1) extra space.

def reverse(head):
    prev_node, current = None, head
    while current is not None:
        next_node = current.next
        current.next = prev_node
        prev_node = current
        current = next_node
    return prev_node
function reverse(head: ListNode | null): ListNode | null {
  let prevNode: ListNode | null = null, current = head;
  while (current !== null) {
    const nextNode = current.next;
    current.next = prevNode;
    prevNode = current;
    current = nextNode;
  }
  return prevNode;
}

    return prevNode;

6. How to remember it forever

Memory hook: "Save, flip, step, step"Four lines, always in this order: next_node = current.next → current.next = prev_node → prev_node = current → current = next_node. Each line's left side is the previous line's right side, like a chain.
How this hook works: what “Save, flip, step, step” means

What the slogan means, phrase by phrase

“Save”
next_node = current.next: remember the rest of the line before you let go of it.
“flip”
current.next = prev_node: turn this arrow around so it points backwards.
“step”
prev_node = current: the node you just flipped is now the front of the reversed part.
“step”
current = next_node: move on to the part you saved.

Why this picture fits the pattern: Reversing a list is four pointer moves repeated, and the order is everything: flip before you save and the rest of the list is lost. The slogan is the four lines in order, one word per line.

Problem: Reverse the nodes of the list k at a time. If the last group has fewer than k nodes, leave it as it is. Only change links, not values.

Output: [2,1,4,3,5]
Example 2
Input: head = [1,2,3,4,5], k = 3
Output: [3,2,1,4,5]

Constraints: The number of nodes in the list is n. · 1 ≤ k ≤ n ≤ 5000 · 0 ≤ Node.val ≤ 1000

Hint 1

Handle the list one group of k nodes at a time. Check that a full group exists before touching it.

Hint 2

Reverse the group with prev/cur/next, then reconnect: the node before the group points to the new group head, and the old group head (now its tail) points to what came after.

From brute force to the pattern: Copying values into an array, reversing chunks and rebuilding uses O(n) space. Reversing each full group in place with careful reconnection is O(n) time and O(1) space; a dummy node avoids special-casing the first group.

Spot it: "reverse" + "k at a time" + "only nodes may be changed": repeated sub-list reversal with stitching.

Key insight: keep group_prev (the node before the group). First check that k nodes exist (find kth). Reverse the group with prev_node initialised to group_next instead of None: that way the group's old first node automatically points to the rest of the list. Then hook group_prev.next = kth and move group_prev to the old first node (now the group's tail).

Approach:

  1. Make a dummy before head; group_prev = dummy.
  2. Walk k steps from group_prev to find kth. If you hit None, return dummy.next.
  3. Save group_next = kth.next. Reverse the k nodes with prev_node starting at group_next.
  4. Stitch: group_prev.next = kth (the new front). The old first node is now the group's tail, so it becomes the next group_prev.
  5. Repeat.
class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        # The head changes after the first group, so put a dummy in front.
        dummy = ListNode(0, head)
        # group_prev = the node just BEFORE the group we are working on.
        group_prev = dummy
        while True:
            # --- 1) Is there a full group of k nodes? ---
            # Walk k steps from group_prev. We land on the k-th node of the group.
            kth = group_prev
            for step in range(k):
                kth = kth.next
                if kth is None:
                    # Fewer than k nodes are left: leave them as they are.
                    return dummy.next
            # The first node AFTER this group (it may be None).
            group_next = kth.next
            # The group's first node. After reversing, it will be the group's LAST node.
            group_first = group_prev.next

            # --- 2) Reverse the k nodes of this group (save, flip, step, step). ---
            # Trick: prev_node starts at group_next instead of None, so the old
            # first node automatically ends up pointing at the rest of the list.
            prev_node = group_next
            current = group_first
            while current is not group_next:
                next_node = current.next      # save the rest
                current.next = prev_node      # flip the arrow
                prev_node = current           # step prev_node
                current = next_node           # step current

            # --- 3) Stitch the front of the group back in. ---
            # kth was the group's last node; now it is the group's first node.
            group_prev.next = kth
            # The old first node is now the group's tail, so it is
            # the node BEFORE the next group.
            group_prev = group_first
function reverseKGroup(head: ListNode | null, k: number): ListNode | null {
    // The head changes after the first group, so put a dummy in front.
    const dummy = new ListNode(0, head);
    // groupPrev = the node just BEFORE the group we are working on.
    let groupPrev = dummy;
    while (true) {
        // --- 1) Is there a full group of k nodes? ---
        // Walk k steps from groupPrev. We land on the k-th node of the group.
        let kth: ListNode | null = groupPrev;
        for (let step = 0; step < k; step++) {
            kth = kth!.next;
            if (kth === null) {
                // Fewer than k nodes are left: leave them as they are.
                return dummy.next;
            }
        }
        // The first node AFTER this group (it may be null).
        const groupNext = kth!.next;
        // The group's first node. After reversing, it will be the group's LAST node.
        const groupFirst = groupPrev.next!;

        // --- 2) Reverse the k nodes of this group (save, flip, step, step). ---
        // Trick: prevNode starts at groupNext instead of null, so the old
        // first node automatically ends up pointing at the rest of the list.
        let prevNode = groupNext;
        let current: ListNode | null = groupFirst;
        while (current !== groupNext) {
            const nextNode: ListNode | null = current!.next;  // save the rest
            current!.next = prevNode;     // flip the arrow
            prevNode = current;           // step prevNode
            current = nextNode;           // step current
        }

        // --- 3) Stitch the front of the group back in. ---

    public ListNode reverseKGroup(ListNode head, int k) {
        // The head changes after the first group, so put a dummy in front.
        ListNode dummy = new ListNode(0, head);
        // groupPrev = the node just BEFORE the group we are working on.
        ListNode groupPrev = dummy;
        while (true) {
            // --- 1) Is there a full group of k nodes? ---
            // Walk k steps from groupPrev. We land on the k-th node of the group.
            ListNode kth = groupPrev;
            for (int step = 0; step < k; step++) {
                kth = kth.next;
                if (kth == null) {
                    // Fewer than k nodes are left: leave them as they are.
                    return dummy.next;
                }
            }
            // The first node AFTER this group (it may be null).
            ListNode groupNext = kth.next;
            // The group's first node. After reversing, it will be the group's LAST node.
            ListNode groupFirst = groupPrev.next;

            // --- 2) Reverse the k nodes of this group (save, flip, step, step). ---
            // Trick: prevNode starts at groupNext instead of null, so the old
            // first node automatically ends up pointing at the rest of the list.
            ListNode prevNode = groupNext;
            ListNode current = groupFirst;
            while (current != groupNext) {
                ListNode nextNode = current.next;  // save the rest
                current.next = prevNode;      // flip the arrow
                prevNode = current;           // step prevNode
                current = nextNode;           // step current
            }

            // --- 3) Stitch the front of the group back in. ---
            // kth was the group's last node; now it is the group's first node.
            groupPrev.next = kth;
            // The old first node is now the group's tail, so it is
            // the node BEFORE the next group.
            groupPrev = groupFirst;
        }

        // Reverse everything AFTER head. newHead is the old last node.
        ListNode newHead = reverseListRecursive(head.next);
        // head.next still points to the node that came right after head.
        // That node is now the TAIL of the reversed rest.
        ListNode second = head.next;
        // Hang head after it: the node after me now points back to me.
        second.next = head;
        // head is the new tail (for now), so it must point at nothing.
        head.next = null;
        return newHead;
    }
}

What the code is doing, line by line:

  1. reverseList (iterative): prev_node = None (nothing reversed yet) and current = head.
  2. Inside while current is not None: do the four lines in order: save next_node = current.next, flip current.next = prev_node, step prev_node = current, step current = next_node.
  3. When current becomes None, prev_node is the old tail = new head, so return it.
  4. reverseListRecursive: base case: if the list is empty or has one node, it is already reversed, so return head.
  5. new_head = self.reverseListRecursive(head.next) trusts the recursion to reverse everything after head. new_head is the old last node and never changes on the way back up.
  6. second = head.next: this node was right after head, and after the recursive call it is the tail of the reversed rest.
  7. second.next = head hangs head after it; head.next = None makes head the new tail (otherwise we would get a 2-node cycle).
  8. Return new_head so every level passes the same new head upwards.

8. Common mistakes

Flipping before savingWriting current.next = prev_node before next_node = current.next loses the rest of the list forever.
Returning head or currentAfter the loop, current is None and head is the new tail. Return prev_node.
No dummy node for partial reversalIf left = 1, there's no "node before". A dummy removes that special case, so return dummy.next.
Forgetting to stitch the endsAfter reversing a part, connect the node before it to the new front and the new tail to the node after it. Otherwise you get a cut-off list or a cycle.

Problem: Do the list's values read the same forwards and backwards, using only O(1) extra space?

Hint 1

Copying the values into an array and comparing with its reverse uses O(n) space. How can you avoid that?

Hint 2

Find the middle, reverse the second half in place, then compare the two halves node by node.

From brute force to the pattern: An array copy or a stack gives O(n) space. Middle-finding plus an in-place reversal of the second half compares the halves with O(1) extra space (and you can reverse it back afterwards).

Spot it: Comparing the front with the back means reading the second half backwards. Reverse it in place instead of copying into an array.

Approach:

  1. Find the start of the second half with fast & slow.
  2. Reverse the second half with save / flip / step / step.
  3. Walk from head and from the reversed half together, comparing values.
  4. Any mismatch → False; otherwise True.
class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        # --- 1) Move slow to the start of the second half (fast & slow). ---
        slow = head
        fast = head
        while fast is not None and fast.next is not None:
            slow = slow.next          # 1 step
            fast = fast.next.next     # 2 steps

        # --- 2) Reverse the second half in place. ---
        prev_node = None
        current = slow
        while current is not None:
            next_node = current.next      # save
            current.next = prev_node      # flip
            prev_node = current           # step
            current = next_node           # step

        # --- 3) Walk both halves together and compare values. ---
        front = head          # start of the first half
        back = prev_node      # start of the reversed second half
        while back is not None:
            if front.val != back.val:
                # One mismatch is enough: not a palindrome.
                return False
            front = front.next
            back = back.next
        # Every pair matched.
        return True

The result interleaves the first half with the reversed second half.

Hint 2

From brute force to the pattern: Copying the nodes into an array and re-linking with two indices is O(n) time but O(n) space. Middle + reverse + merge does it in place in O(n) time and O(1) space.

Spot it: You need the back half in reverse order → split at the middle, reverse the second half, then weave.

Approach:

  1. Fast/slow with while fast.next and fast.next.next puts slow at the end of the first half.
  2. Cut after slow and reverse the second half.
  3. Weave: front.next = back, back.next = front_next, then advance both.
  4. Stop when the (shorter or equal) second half runs out.

Hint 1

Rotating by the list's length changes nothing, so use k % length.

Hint 2

Make the list circular, then break it length − k nodes after the old head.

From brute force to the pattern: Rotating one step at a time is O(n · k). Measuring the length once, closing the ring and cutting in the right place is O(n).

Spot it: Re-linking pointers in place, like reversal. The trick is to close the list into a ring and cut it at the right spot.

Approach:

  1. Measure the length and find the tail.
  2. shift = k % length; if it's 0, return head unchanged.
  3. Link tail.next = head to make a ring.
  4. Walk length − shift − 1 steps from head to the new tail; the new head is new_tail.next; then cut the ring.
class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        # 0 or 1 node: rotating changes nothing.
        if head is None or head.next is None:
            return head

        # --- 1) Measure the length and find the tail. ---
        length = 1
        tail = head
        while tail.next is not None:
            tail = tail.next
            length = length + 1

        # --- 2) Rotating by 'length' places changes nothing, so drop full turns. ---
        # shift = how many places we really need to rotate.
        shift = k % length
        if shift == 0:
            return head

        # --- 3) Close the list into a ring. ---
        tail.next = head

        # --- 4) The new tail is length - shift - 1 steps from the head. ---
        new_tail = head
        for step in range(length - shift - 1):
            new_tail = new_tail.next
        # The node after the new tail is the new head.
        new_head = new_tail.next
        # Cut the ring open.
        new_tail.next = None
        return new_head

Spot it: Reversing chunks in place → k-group reversal where k grows each time and a parity check decides whether to reverse.

Approach:

  1. group_prev = head (group 1 has size 1 and is never reversed); group_size = 2.
  2. Count up to group_size nodes after group_prev to get the group's real length.
  3. If it's even, reverse those nodes with prev_node starting at group_next (the node after the group), set group_prev.next = prev_node, and move group_prev to group_first (the old first node).

Problem: Swap the values of the k-th node from the start and the k-th node from the end.

Output: [7,9,6,6,8,7,3,0,9,5]

Constraints: The number of nodes in the list is n. · 1 ≤ k ≤ n ≤ 10⁵ · 0 ≤ Node.val ≤ 100

Hint 1

How do you find the k-th node from the end in one pass?

Hint 2

Keep two pointers k − 1 apart.

From brute force to the pattern: Copying to an array is O(n) space; two pointers are O(1).

Spot it: The k-th from the end is found with the gap technique: once a pointer has gone k steps, start a second pointer at the head; when the first reaches the end, the second is k from the end. Then swap the two values.

Why not another pattern? Counting the length first works too (two passes); copying to an array uses O(n) space.

Approach:

  1. Walk k − 1 steps from the head: that's first.
  2. fast = first, second = head; advance both until fast is the last node.
  3. Swap first.val and second.val.
class Solution:
    def swapNodes(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        first = head
        for _ in range(k - 1):
            first = first.next  # k-th from the start
        fast, second = first, head
        while fast.next:
            fast = fast.next  # keep a gap of k - 1 nodes
            second = second.next
        first.val, second.val = second.val, first.val  # k-th from the end is `second`
        return head
function swapNodes(head: ListNode | null, k: number): ListNode | null {
    let first = head!;
    for (let step = 0; step < k - 1; step++) {
        first = first.next!;  // k-th from the start
    }
    let fast = first;
    let second = head!;
    while (fast.next !== null) {
        fast = fast.next;  // keep a gap of k - 1 nodes
        second = second.next!;
    }
    [first.val, second.val] = [second.val, first.val];  // k-th from the end is `second`
    return head;
}
class Solution {
    public ListNode swapNodes(ListNode head, int k) {
        ListNode first = head;
        for (int step = 0; step < k - 1; step++) {
            first = first.next;  // k-th from the start
        }
        ListNode fast = first;
        ListNode second = head;
        while (fast.next != null) {
            fast = fast.next;  // keep a gap of k - 1 nodes
            second = second.next;
        }
        int temp = first.val;  // k-th from the end is `second`: swap the values
        first.val = second.val;
        second.val = temp;
        return head;
    }
}

What the code is doing, line by line:

  1. When fast is at the last node, second is k − 1 nodes behind it: the k-th from the end.
  2. Swapping values is allowed and avoids relinking edge cases.
