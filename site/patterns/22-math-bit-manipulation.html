1. What is this pattern for?

A cashier asked for 230 doesn't multiply by 2 thirty times: they square 2 → 4 → 16 → 256 … five times. Math-and-bits problems are like that: the slow way is obvious, and one observation about how numbers are built (binary digits, prime factors, divisors) makes it instant.

The recurring tools:

  • Binary exponentiation. xⁿ in O(log n) by squaring: Pow(x, n), Super Pow, Count Good Numbers, matrix powers.
  • XOR tricks. a ^ a = 0, a ^ 0 = a: pairs cancel. Single Number I/II/III, XOR subsequences.
  • Per-bit reasoning. Bits are independent under AND/OR/XOR, so solve one bit position at a time (Minimum Flips, Single Number II).
  • Primes and divisors. Sieve of Eratosthenes, divisor pairs up to √n, gcd counting by multiples.
  • Counting formulas. Stars and bars, binomials, parity arguments: Bulb Switcher, Reach a Number, Count Valid Sequences.

2. How it works (bisected)

  1. Write the slow version (multiply n times, try every number, check every pair) and its cost.
  2. Look at the structure of the numbers: their binary digits, their prime factors, their divisors, their parity.
  3. Find the invariant that the slow version is secretly computing: "pairs cancel under XOR", "divisors pair up", "each bit is independent", "only perfect squares have an odd number of divisors".
  4. Replace the loop with the invariant: a formula, a loop over 32 bits, or a loop over log n squarings.
  5. Mind the edges: negative numbers, 32-bit overflow, modulo 10⁹ + 7, and 0 / 1.

3. Seeing a problem: how to spot Math / Bit Manipulation

Trigger words

  • "without using * / %", "without + −", "in O(1) extra space" with numbers that appear twice / three times
  • huge exponents or counts: n up to 10⁹ or 10¹⁵, "return modulo 10⁹ + 7"
  • "bitwise AND / OR / XOR", "number of 1 bits", "power of two"
  • "count primes", "divisors", "gcd of all pairs", "factorial"
  • a simulation over a huge range (bulbs, steps on a number line)

Shape of the input

  • One or two integers, often enormous.
  • An array where every value appears k times except a few.
  • Brute-force smell: a loop up to n with n = 10⁹, or all pairs of an array of 10⁵.
The one question to ask"Is there a property of the numbers themselves (bits, factors, parity) that makes most of this work unnecessary?"

4. When to use it, and when not to

Reach for math / bits when…Prefer something else when…
An exponent or count is huge (10⁹+) and the step is a multiplicationThe step isn't a product or linear map: look for DP or a closed form
Values appear in pairs/triples and you need O(1) spaceYou may use O(n) space and clarity matters: a hash map is fine
Operations are bitwise and bits don't interactCarries connect the bits (addition): handle them explicitly
You need primes or divisors of many numbersYou need them for one number: trial division up to √n is enough

Cost: fast power is O(log n), per-bit loops are O(32 · n), the sieve is O(n log log n), and gcd counting over multiples is O(M log M) by the harmonic series.

5. The templates, step by step (Python, TypeScript, Java)

Three math templates that show up again and again: A fast exponentiation (square-and-multiply, O(log n) multiplications), B XOR to cancel pairs (find the single number), C the sieve of Eratosthenes (all primes below n). Each is a few lines; each rests on one fact worth saying out loud in the interview.

The template. Use the bit first, then square: the order matters.

def fast_pow(x, n, m):
    result = 1
    x %= m
    while n:
        if n & 1:
            result = result * x % m
        x = x * x % m
        n >>= 1
    return result
function fastPow(x: bigint, n: bigint, m: bigint): bigint {
  let result = 1n;
  x %= m;
  while (n > 0n) {
    if (n & 1n) result = (result * x) % m;
    x = (x * x) % m;
    n >>= 1n;
  }
  return result;
}
static long fastPow(long x, long n, long m) {
    long result = 1;
    x %= m;
    while (n > 0) {
        if ((n & 1) == 1) result = result * x % m;
        x = x * x % m;
        n >>= 1;
    }
    return result;
}

def single_number(nums):
    acc = 0
    for v in nums:
        acc ^= v
    return acc
function singleNumber(nums: number[]): number {
  let acc = 0;

}

The template. Two loops; the inner one starts at p·p.

def sieve(n):
    is_prime = [True] * n
    is_prime[0:2] = [False, False]
    p = 2
    while p * p < n:
        if is_prime[p]:
            for multiple in range(p * p, n, p):
                is_prime[multiple] = False
        p += 1
    return [i for i in range(n) if is_prime[i]]
function sieve(n: number): number[] {
  const isPrime: boolean[] = new Array(n).fill(true);
  isPrime[0] = isPrime[1] = false;
  for (let p = 2; p * p < n; p++) {
    if (isPrime[p]) {
      for (let m = p * p; m < n; m += p) isPrime[m] = false;
    }
  }
  return isPrime.flatMap((ok, i) => (ok ? [i] : []));
}
static List<Integer> sieve(int n) {
    boolean[] isPrime = new boolean[n];
    Arrays.fill(isPrime, true);
    isPrime[0] = isPrime[1] = false;
    for (int p = 2; (long) p * p < n; p++) {
        if (isPrime[p]) {
            for (int m = p * p; m < n; m += p) isPrime[m] = false;
        }
    }
    List<Integer> primes = new ArrayList<>();
    for (int i = 0; i < n; i++) if (isPrime[i]) primes.add(i);
    return primes;
}

6. How to remember it forever

Memory hook: "Square and skip"Exponents: square the base, multiply only on set bits. XOR: pairs vanish. Bits: one column at a time.
How this hook works: what “Square and skip” means

What the slogan means, phrase by phrase

“Square”
In fast exponentiation, square the base every round: x, x², x⁴, x⁸ …
“and skip”
Multiply that power into the result only when the matching bit of the exponent is 1. Skip it otherwise.
“XOR: pairs vanish”
a ^ a = 0 and a ^ 0 = a, so XOR-ing everything cancels every pair and leaves the odd one out.
“Bits: one column at a time”
Each bit position is independent, so you can count or decide per column.

Why this picture fits the pattern: Math and bit problems each hide one structural fact (binary digits, pairs cancelling, divisors coming in pairs) that turns a slow loop into O(log n) or O(1). The slogan bundles the three you'll use most.

Watch it on numbers

Compute 3¹³. 13 in binary is 1101 = 8 + 4 + 1.

  1. Bit 1 is set: result = 3. Square: x = 9.
  2. Bit 0: skip. Square: x = 81.
  3. Bit 1: result = 3 × 81 = 243. Square: x = 6561.
  4. Bit 1: result = 243 × 6561 = 1,594,323. That's 4 rounds instead of 12 multiplications.
  5. XOR on [4, 1, 2, 1, 2]: the 1s cancel, the 2s cancel, 4 is left.

The trap it saves you from

Forgetting % m after every multiply (the numbers grow huge and slow), and Python's negative integers behaving as if they had infinite bits. Mask with & 0xFFFFFFFF for 32-bit answers.

It still works when…

Single Number is pairs vanishing. Counting Bits uses bits[i] = bits[i >> 1] + (i & 1). Bulb Switcher: a bulb is toggled once per divisor, divisors come in pairs, so only perfect squares stay on.

"Bits are independent, divisors come in pairs, squares grow fast."

Safety rule

"Mask, mod, and mind the sign." 32-bit masks in Python, mod after every multiply, and negative numbers.

Hint 2

Use the binary representation of n.

From brute force to the pattern: n multiplications vs log n squarings.

Spot it: Binary exponentiation: xⁿ is the product of x^(2^k) over the set bits of n. Square the base each step.

Why not another pattern? Multiplying n times is O(n) with |n| up to 2³¹.

Approach:

  1. If n < 0: x = 1/x, n = −n.
  2. While n: if n & 1, result *= x; x *= x; n >>= 1.
class Solution:
    def myPow(self, x: float, n: int) -> float:
        if n < 0:
            x, n = 1 / x, -n  # x^-n = (1/x)^n
        result = 1.0
        while n:
            if n & 1:
                result *= x  # this power of two is part of n
            x *= x  # x, x^2, x^4, x^8, ...
            n >>= 1
        return result
function myPow(x: number, n: number): number {
    if (n < 0) {
        x = 1 / x;  // x^-n = (1/x)^n
        n = -n;
    }
    let result = 1.0;
    while (n) {
        if (n % 2 === 1) {
            result *= x;  // this power of two is part of n
        }
        x *= x;  // x, x^2, x^4, x^8, ...
        n = Math.floor(n / 2);  // n can be 2^31: too big for >>
    }
    return result;
}
class Solution {
    public double myPow(double x, int n) {
        long e = n;  // long: -n overflows an int when n = -2^31
        if (e < 0) {
            x = 1 / x;  // x^-n = (1/x)^n
            e = -e;
        }
        double result = 1.0;
        while (e != 0) {
            if ((e & 1) == 1) {
                result *= x;  // this power of two is part of n
            }
            x *= x;  // x, x^2, x^4, x^8, ...
            e >>= 1;
        }
        return result;
    }
}

                hi = mid;

        while (x) {
            digits.push(x % k);
            x = Math.floor(x / k);
        }
        return digits.join(",") === [...digits].reverse().join(",");
    };

    let total = 0, found = 0;
    let length = 1;
    while (found < n) {
        const half = Math.floor((length + 1) / 2);
        for (let first = 10 ** (half - 1); first < 10 ** half; first++) {  // increasing halves -> increasing palindromes
            const s = String(first);
            const pal = Number(s + [...s].reverse().join("").slice(length % 2));  // mirror (skip the middle digit for odd length)
            if (baseKPalindrome(pal)) {
                total += pal;
                found += 1;
                if (found === n) {
                    break;
                }
            }
        }
        length += 1;
    }
    return total;
}
class Solution {
    public long kMirror(int k, int n) {
        long total = 0;
        int found = 0;
        int length = 1;
        while (found < n) {
            int half = (length + 1) / 2;
            long from = pow10(half - 1), to = pow10(half);
            for (long first = from; first < to; first++) {  // increasing halves -> increasing palindromes
                String s = Long.toString(first);
                String mirror = new StringBuilder(s).reverse().substring(length % 2);  // skip the middle digit for odd length
                long pal = Long.parseLong(s + mirror);
                if (baseKPalindrome(pal, k)) {
                    total += pal;
                    found += 1;
                    if (found == n) {
                        break;
                    }
                }
            }
            length += 1;
        }
        return total;
    }

    private boolean baseKPalindrome(long x, int k) {
        List<Long> digits = new ArrayList<>();
        while (x != 0) {
            digits.add(x % k);
            x /= k;
        }
        for (int i = 0, j = digits.size() - 1; i < j; i++, j--) {
            if (!digits.get(i).equals(digits.get(j))) {
                return false;
            }
        }
        return true;
    }

    private long pow10(int e) {
        long out = 1;
        for (int t = 0; t < e; t++) {
            out *= 10;
        }
        return out;
    }
}

What the code is doing, line by line:

  1. For a fixed length, palindromes increase with their first half, so they're produced in order.
  2. s[::-1][length % 2:] drops the repeated middle digit for odd lengths.
  3. Base-10 palindromes are rare (about √N up to N), so the search is fast.

Medium 2571. Minimum Operations to Reduce an Integer to 0 Microsoft Math

Problem: Add or subtract any power of 2 per operation. Return the fewest operations to make n zero.

Solve it on LeetCode ↗

Example 1
Input: n = 39
Output: 3
Explanation: We can do the following operations: - Add 2⁰ = 1 to n, so now n = 40. - Subtract 2³ = 8 from n, so now n = 32. - Subtract 2⁵ = 32 from n, so now n = 0. It can be shown that 3 is the minimum number of operations we need to make n equal to 0.
Example 2
Input: n = 54
Output: 3
Explanation: We can do the following operations: - Add 2¹ = 2 to n, so now n = 56. - Add 2³ = 8 to n, so now n = 64. - Subtract 2⁶ = 64 from n, so now n = 0. So the minimum number of operations is 3.

Constraints: 1 ≤ n ≤ 10⁵

Hint 1

Look at n in binary.

Hint 2

When is adding a power of two better than subtracting one?

From brute force to the pattern: BFS over integers is slow; the bit scan is O(log n).

Spot it: A bit manipulation greedy: scan from the lowest bit. A single 1 (next bit 0) costs one subtraction. A run of 1s (next bit also 1) is cheaper to clear by adding 1, which turns the run into one carry. This builds the non-adjacent form, which has the fewest non-zero digits.

Why not another pattern? BFS over values works but is far slower and unnecessary.

Approach:

  1. While n: if the lowest bit is 1: if the next bit is also 1, n += 1, else n −= 1; count an operation.
  2. Shift right.
class Solution:
    def minOperations(self, n: int) -> int:
        ops = 0
        while n:
            if n & 1:
                if n & 2:
                    n += 1  # a run of 1s: one carry clears the whole run
                else:
                    n -= 1  # a lone 1: just subtract it
                ops += 1
            n >>= 1
        return ops

Explanation: 5 = 2 + 3

Output: 3
Explanation: 9 = 4 + 5 = 2 + 3 + 4

Constraints: 1 ≤ n ≤ 10⁹

Hint 1

Write the sum of k consecutive numbers starting at x.

Hint 2

For which k does an integer x ≥ 1 exist?

From brute force to the pattern: All start/length pairs are O(n²); iterating k is O(√n).

Spot it: Math: a run of k numbers starting at x sums to k·x + k(k − 1)/2. For each length k, check whether n − k(k − 1)/2 is a positive multiple of k. Only k up to about √(2n) can fit.

Why not another pattern? Trying every start and length is O(n²).

Approach:

  1. For k = 1, 2, … while k(k − 1)/2 < n:
  2. If (n − k(k − 1)/2) % k == 0, count it.

    def consecutiveNumbersSum(self, n: int) -> int:

        k = 1

            if (n - k * (k - 1) // 2) % k == 0:
                ways += 1  # x = (n - k(k-1)/2) / k is a positive integer
            k += 1
        return ways

Medium 477. Total Hamming Distance Apple Array

Problem: Return the sum of Hamming distances over all pairs of numbers.

Solve it on LeetCode ↗

Example 1
Input: nums = [4,14,2]
Output: 6
Explanation: In binary representation, the 4 is 0100, 14 is 1110, and 2 is 0010 (just showing the four bits relevant in this case). The answer will be: HammingDistance(4, 14) + HammingDistance(4, 2) + HammingDistance(14, 2) = 2 + 2 + 2 = 6.
Example 2
Input: nums = [4,14,4]
Output: 4

Constraints: 1 ≤ nums.length ≤ 10⁴ · 0 ≤ nums[i] ≤ 10⁹ · The answer for the given input will fit in a 32-bit integer.

Hint 1

Look at a single bit position across all numbers.

Hint 2

How many pairs differ at that bit?

From brute force to the pattern: All pairs: O(32 n²); per-bit counting: O(32 n).

Spot it: Bits are independent → look at one bit position at a time: with c ones among n numbers, exactly c · (n − c) pairs differ at that bit.

Why not another pattern? Comparing all pairs is O(n² · 32).

Approach:

  1. For each of 32 bits: c = numbers with that bit set.
  2. Add c · (n − c).
class Solution:
    def totalHammingDistance(self, nums: List[int]) -> int:
        n = len(nums)
        total = 0
        for b in range(32):
            ones = sum((x >> b) & 1 for x in nums)  # numbers with bit b set
            total += ones * (n - ones)  # each (one, zero) pair differs here
        return total
