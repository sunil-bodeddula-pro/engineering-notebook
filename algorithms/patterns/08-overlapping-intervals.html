Overlapping Intervals

Sort the ranges by where they start, then walk left to right. Once sorted, you only ever compare an interval with the one just before it.

1. What is this pattern for?

Imagine your calendar is a mess of sticky notes, one per meeting: "9–10", "9:30–11", "1–2"… dropped in random order. To find your busy blocks, you first line the notes up by start time. Then you go down the line: if the next note starts before the current block ends, you stick it onto that block (stretching it if needed). If it starts later, there's a gap, and a new block begins. One pass and your day is clean.

An interval is a pair [start, end]: a meeting, a booking, a range of numbers. Many problems ask how a collection of intervals overlap: merge them, insert a new one, count how many overlap at once, remove the fewest to make them disjoint, or find the free gaps.

Checking every pair is O(n²). The trick is to sort first (O(n log n)). After sorting by start, overlaps can only happen between neighbors in the line, so one linear sweep finishes the job.

Two intervals a and b overlap exactly when a.start ≤ b.end and b.start ≤ a.end. After sorting by start, that becomes simply next.start ≤ current.end.

2. How it works (bisected)

  1. Sort by start (for merging, inserting, counting rooms) or by end (for the greedy "keep the most non-overlapping" problems). This is the step that makes everything else linear.
  2. Keep a "current" interval: usually merged[-1], the last block in your answer.
  3. For each next interval, ask one question: does it start at or before the current one ends? (s ≤ cur_end)
  4. Overlap → extend: cur_end = max(cur_end, e). Use max because the new interval may sit entirely inside the current one.
  5. No overlap → close and open: the current block is final. Start a new one with [s, e].
  6. Need "how many at once"? Keep a min-heap of end times (the rooms in use), or sweep sorted +1/−1 events. The biggest count you see is the answer.

Counting simultaneous overlaps (how many rooms do we need?): sort by start, and keep a min-heap of end times. The heap's top tells you which room frees up first.

3. Seeing a problem: how to spot Overlapping Intervals

Trigger words

  • "intervals", "ranges", "meetings", "bookings", "schedules", "time slots"
  • "merge overlapping", "insert a new interval"
  • "minimum number of rooms / platforms / arrows"
  • "remove the fewest intervals so none overlap"
  • "common free time", "intersection of two lists of intervals"

Shape of the input

  • A list of pairs [start, end] (sometimes objects with .start and .end).
  • Usually unsorted, which is your cue to sort first.
  • The answer depends on which ranges touch or cross each other.
  • The brute force compares every pair of intervals: O(n²).
The one question to ask"If I lined these ranges up by start time, would I only need to compare each one with the one before it?" If yes, sort and sweep.

5. The templates, step by step (Python, TypeScript, Java)

Interval problems start the same way, sort first, then sweep left to right, but they sort by different ends and keep different state. A merges overlaps (sort by start, extend the last block). B counts how many overlap at once (sort by start, a min-heap of end times = rooms in use). C keeps as many non-overlapping intervals as possible (sort by end, greedily keep the one that finishes first).

TypeScript has no built-in heap. The TypeScript templates on this page use this small MinHeap class (Python has heapq, Java has PriorityQueue). 
class MinHeap<T> {
  items: T[] = [];
  less: (x: T, y: T) => boolean;
  constructor(less: (x: T, y: T) => boolean) { this.less = less; }
  get size(): number { return this.items.length; }
  peek(): T | undefined { return this.items[0]; }
  push(x: T): void {
    const a = this.items;
    a.push(x);
    for (let i = a.length - 1; i > 0; ) {            // bubble up
      const p = (i - 1) >> 1;
      if (!this.less(a[i], a[p])) break;
      [a[i], a[p]] = [a[p], a[i]];
      i = p;
    }
  }
  pop(): T | undefined {
    const a = this.items, top = a[0], last = a.pop()!;
    if (a.length > 0) {
      a[0] = last;
      for (let i = 0; ; ) {                            // sink down
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < a.length && this.less(a[l], a[m])) m = l;
        if (r < a.length && this.less(a[r], a[m])) m = r;
        if (m === i) break;
        [a[i], a[m]] = [a[m], a[i]];
        i = m;
      }
    }
    return top;
  }
}

Pass a "less than" function: new MinHeap<number>((a, b) => a < b) is a min-heap, (a, b) => a > b a max-heap. Push and pop are O(log n), peek is O(1).

def merge(intervals):
    merged = []
    for start, end in sorted(intervals):
        if merged and start <= merged[-1][1]:

function merge(intervals: number[][]): number[][] {
  const merged: number[][] = [];
  for (const [start, end] of [...intervals].sort((a, b) => a[0] - b[0])) {
    const last = merged[merged.length - 1];
    if (last && start <= last[1]) {
      last[1] = Math.max(last[1], end);
    } else {
      merged.push([start, end]);
    }
  }
  return merged;
}

    int[][] sorted = intervals.clone();

What it keepsA min-heap of end times: one entry per room in use; the top is the room freed first.

import heapq

def min_rooms(intervals):
    room_ends = []
    for start, end in sorted(intervals):
        if room_ends and room_ends[0] <= start:
            heapq.heappop(room_ends)
        heapq.heappush(room_ends, end)
    return len(room_ends)
function minRooms(intervals: number[][]): number {
  const roomEnds = new MinHeap<number>((a, b) => a < b);
  for (const [start, end] of [...intervals].sort((a, b) => a[0] - b[0])) {
    if (roomEnds.size > 0 && roomEnds.peek()! <= start) {
      roomEnds.pop();
    }
    roomEnds.push(end);
  }
  return roomEnds.size;
}
static int minRooms(int[][] intervals) {
    int[][] sorted = intervals.clone();
    Arrays.sort(sorted, (a, b) -> Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> roomEnds = new PriorityQueue<>();
    for (int[] iv : sorted) {
        if (!roomEnds.isEmpty() && roomEnds.peek() <= iv[0]) {
            roomEnds.poll();
        }
        roomEnds.offer(iv[1]);
    }
    return roomEnds.size();
}

6. How to remember it forever

Memory hook: "Line up the sticky notes"Sort by start, then each note either sticks to the block above it (overlap → stretch with max) or starts a new block (gap).
How this hook works: what “Line up the sticky notes” means

What the slogan means, phrase by phrase

“Sticky notes”
Intervals [start, end], given in random order.
“Line up”
Sort by start first. After that, a note can only overlap the block directly above it, never one further back.
“sticks to the block above it (overlap → stretch with max)”
If start <= block_end, the note joins that block, and its end becomes max(block_end, end).
“or starts a new block (gap)”
If it starts after the block ends, there's free time in between, so a new block begins.

Why this picture fits the pattern: Interval problems are hopeless in random order: anything might overlap anything. Sorting by start turns them into a single top-to-bottom pass that compares each note with one block.

Problem: Given a list of intervals, merge all overlapping ones and return the non-overlapping result. Touching intervals like [1,4] and [4,5] count as overlapping.

Solve it on LeetCode ↗ · Video walkthrough ↗

Example 1
Input: intervals = [[1,3],[2,6],[8,10],[15,18]]
Output: [[1,6],[8,10],[15,18]]
Explanation: Since intervals [1,3] and [2,6] overlap, merge them into [1,6].
Example 2
Input: intervals = [[1,4],[4,5]]
Output: [[1,5]]
Explanation: Intervals [1,4] and [4,5] are considered overlapping.

Constraints: 1 ≤ intervals.length ≤ 10⁴ · intervals[i].length == 2 · 0 ≤ starti ≤ endi ≤ 10⁴

Hint 1

If the intervals were sorted by start, where could an interval overlap?

Hint 2

After sorting, each interval either overlaps the last merged block (start ≤ its end) or starts a new block.

From brute force to the pattern: Comparing every pair and merging repeatedly until nothing changes is O(n²) or worse. Sorting by start puts every possible overlap next to each other, so one sweep merges everything: O(n log n).

Spot it: The word "merge" plus a list of ranges: this is the canonical problem of the pattern.

Key insight: Once sorted by start, an interval can only overlap the last merged block. Either stretch that block's end with max, or start a new block. (The first visualization above runs exactly this.)

Approach:

  1. Sort the intervals by start.
  2. Put a copy of the first interval into merged.
  3. For each next [start, end]: if start ≤ last_block[1], they overlap, so set last_block[1] = max(last_block[1], end).
  4. Otherwise there's a gap: append [start, end] as a new block.
  5. Return merged.
from typing import List


def get_start(interval):
    # Sort key helper: the start of an interval is its first number.
    return interval[0]


class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        # Step 1: sort by start so overlapping intervals end up side by side.
        intervals.sort(key=get_start)

        # Step 2: the first interval opens the first merged block.
        # We build a NEW list [start, end] so that stretching the block
        # later never changes the caller's input list.
        first_start = intervals[0][0]
        first_end = intervals[0][1]
        merged = []
        merged.append([first_start, first_end])

        # Step 3: visit every other interval from left to right.
        for i in range(1, len(intervals)):
            start = intervals[i][0]
            end = intervals[i][1]
            last_block = merged[len(merged) - 1]    # block being built
            if start <= last_block[1]:
                # Overlap (touching counts): stretch the block's end.
                # max: [1,10] followed by [2,3] must stay [1,10].
                last_block[1] = max(last_block[1], end)
            else:
                # Gap: the old block is final; this interval opens a new one.
                merged.append([start, end])
        return merged
function merge(intervals: number[][]): number[][] {
    // Step 1: sort by start so overlapping intervals end up side by side.
    intervals.sort((a, b) => a[0] - b[0]);

    // Step 2: the first interval opens the first merged block.
    // We build a NEW array [start, end] so that stretching the block
    // later never changes the caller's input.
    const firstStart = intervals[0][0];
    const firstEnd = intervals[0][1];
    const merged: number[][] = [];
    merged.push([firstStart, firstEnd]);

    // Step 3: visit every other interval from left to right.
    for (let i = 1; i < intervals.length; i++) {
        const start = intervals[i][0];
        const end = intervals[i][1];
        const lastBlock = merged[merged.length - 1];    // block being built
        if (start <= lastBlock[1]) {
            // Overlap (touching counts): stretch the block's end.
            // max: [1,10] followed by [2,3] must stay [1,10].
            lastBlock[1] = Math.max(lastBlock[1], end);
        } else {
            // Gap: the old block is final; this interval opens a new one.
            merged.push([start, end]);
        }
    }
    return merged;
}

        // later never changes the caller's input.
        List<int[]> merged = new ArrayList<>();
        merged.add(new int[] {intervals[0][0], intervals[0][1]});

        // Step 3: visit every other interval from left to right.
        for (int i = 1; i < intervals.length; i++) {
            int start = intervals[i][0];
            int end = intervals[i][1];
            int[] lastBlock = merged.get(merged.size() - 1);    // block being built

                // Overlap (touching counts): stretch the block's end.
                // max: [1,10] followed by [2,3] must stay [1,10].
                lastBlock[1] = Math.max(lastBlock[1], end);
            } else {
                // Gap: the old block is final; this interval opens a new one.
                merged.add(new int[] {start, end});
            }
        }
        return merged.toArray(new int[0][]);

// ---- helper: a small binary heap (TypeScript has no built-in priority queue) ----
// `less(a, b)` decides which item comes out first. The player doesn't step inside it.
class Heap<T> {
    private items: T[] = [];
    private less: (a: T, b: T) => boolean;

    constructor(less: (a: T, b: T) => boolean) {
        this.less = less;
    }

    get size(): number {
        return this.items.length;
    }

    peek(): T {
        return this.items[0];
    }

    push(x: T): void {
        const a = this.items;
        a.push(x);
        let i = a.length - 1;
        while (i > 0) {
            const parent = (i - 1) >> 1;
            if (!this.less(a[i], a[parent])) {
                break;
            }
            [a[i], a[parent]] = [a[parent], a[i]];
            i = parent;
        }
    }

    pop(): T {
        const a = this.items;
        const top = a[0];
        const last = a.pop()!;
        if (a.length > 0) {
            a[0] = last;
            let i = 0;
            while (true) {
                const l = 2 * i + 1;
                const r = l + 1;
                let m = i;
                if (l < a.length && this.less(a[l], a[m])) {
                    m = l;
                }
                if (r < a.length && this.less(a[r], a[m])) {
                    m = r;
                }
                if (m === i) {
                    break;
                }
                [a[i], a[m]] = [a[m], a[i]];
                i = m;
            }
        }
        return top;
    }
}

8. Common mistakes

Forgetting to sortThe whole "only compare with the previous one" idea only works on sorted input. Unsorted [[2,6],[1,3]] would never merge.
Using e instead of max(last_end, e)For [1,10] then [2,3], writing last[1] = e shrinks the block to [1,3]. Always take the max.
Closed vs half-open boundariesDo [1,4] and [4,5] overlap? In 56 yes (<=). For meetings [s, e) (253, 435), no (use ends[0] <= s to reuse, s >= end to keep). Read the problem and choose the comparison on purpose.
Sorting by the wrong keyGreedy "keep the most / remove the fewest" must sort by end. Sorting by start lets one long early interval block many short ones.
Mutating the input while it's aliasedmerged = [intervals[0]] then merged[-1][1] = … also changes intervals[0]. Copy with intervals[0][:] if the caller still needs the input.

Hint 1

Hint 2

From brute force to the pattern: Comparing every pair of meetings is O(n²). Sorting by start means only adjacent meetings can overlap, so one pass checks it: O(n log n).

Spot it: Possible exactly when no two meetings overlap. Sort by start, and any overlap has to show up between neighbors.

Approach:

  1. Sort by start.
  2. For each meeting after the first: if it starts before the previous one ends, return False.
  3. Return True.
from typing import List


class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:

Problem: Two lists of closed intervals are each sorted and internally disjoint. Return their intersection: every range that's covered by both lists.

Solve it on LeetCode ↗

Output: [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]
Example 2
Input: firstList = [[1,3],[5,9]], secondList = []
Output: []

Constraints: 0 ≤ firstList.length, secondList.length ≤ 1000 · firstList.length + secondList.length ≥ 1 · 0 ≤ starti < endi ≤ 10⁹ · endi < starti+1 · 0 ≤ startj < endj ≤ 10⁹ · endj < startj+1

Hint 1

Both lists are sorted and disjoint. Use one pointer per list.

Hint 2

The overlap of two intervals is [max(starts), min(ends)] if non-empty; then advance the interval that ends first.

From brute force to the pattern: Comparing every interval of A with every interval of B is O(m · n). Two pointers walk both sorted lists once, because the interval that ends first can't overlap anything later: O(m + n).

Spot it: Both lists are already sorted, so walk them together with Two Pointers. The overlap of two intervals is [max(starts), min(ends)] when that's non-empty.

Approach:

  1. Start both pointers at 0: i = 0 (into firstList) and j = 0 (into secondList).
  2. Compute overlap_start = max(firstList[i][0], secondList[j][0]) and overlap_end = min(firstList[i][1], secondList[j][1]). If overlap_start ≤ overlap_end, record [overlap_start, overlap_end].
  3. Advance the pointer whose interval ends first. It can't overlap anything further in the other list.
  4. Stop when either list runs out.
from typing import List


class Solution:
    def intervalIntersection(self, firstList: List[List[int]], secondList: List[List[int]]) -> List[List[int]]:
        i = 0                               # position in firstList
        j = 0                               # position in secondList
        result = []
        while i < len(firstList) and j < len(secondList):
            # The overlap starts at the LATER of the two starts ...
            overlap_start = max(firstList[i][0], secondList[j][0])
            # ... and ends at the EARLIER of the two ends.
            overlap_end = min(firstList[i][1], secondList[j][1])
            if overlap_start <= overlap_end:
                # Non-empty overlap: record it.
                result.append([overlap_start, overlap_end])
            # Whichever interval ends first cannot overlap anything else
            # in the other list, so move past it.
            if firstList[i][1] < secondList[j][1]:
                i = i + 1
            else:
                j = j + 1
        return result

Explanation: One arrow needs to be shot for each balloon for a total of 4 arrows.

Hint 1

One arrow at x bursts every balloon whose range contains x. Where should the first arrow go?

Hint 2

Sort by end; shoot at the end of the first balloon, skip every balloon it bursts, repeat.

From brute force to the pattern: Trying arrow positions or subsets is far too slow. Greedy by earliest end is optimal: shooting at the smallest end bursts the most balloons that must be burst anyway. O(n log n).

Spot it: Same greedy as 435: sort by end. Shooting at the earliest end bursts the most balloons that are still standing. Touching counts as overlapping here.

Approach:

  1. Sort balloons by end.
  2. Keep arrow_x = position of the last arrow (start at −∞).
  3. For each balloon: if start > arrow_x, the last arrow misses it, so shoot a new arrow at its end.
  4. Return the arrow count.

def get_balloon_end(balloon):
    # Sort key helper: a balloon [x_start, x_end] ends at its second number.
    return balloon[1]


class Solution:
    def findMinArrowShots(self, points: List[List[int]]) -> int:
        # Greedy: handle the balloon that ends first, first.
        points.sort(key=get_balloon_end)
        arrows = 0
        arrow_x = float("-inf")             # no arrow shot yet

From brute force to the pattern: Simulating each trip over every kilometre is O(n · distance). A difference array (or sorted events) adds each trip in O(1) and checks capacity in one sweep: O(n + max location).

Approach:

  1. Create events (from, +num) and (to, −num).

from typing import List


class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        # Turn every trip into two events (location, change in riders).
        events = []
        for i in range(len(trips)):
            passengers = trips[i][0]
            pickup = trips[i][1]
            dropoff = trips[i][2]
            events.append((pickup, passengers))      # riders get in

    def __init__(self):

        self.ends = []                      # ends, same order as starts

        # GREATER than the new start. The new booking would go there,
        # so its neighbours are at position - 1 (left) and position (right).

  4. The heap's top size (or -1) is the answer for q. Map answers back to the original query order.

    // A min-heap of [size, right] pairs: peek() is always the SMALLEST interval.

    // Sort intervals by their left end.
    intervals.sort((a, b) => a[0] - b[0] || a[1] - b[1]);

    // Build the distinct query values in increasing order.
    const sortedQueries = [...queries].sort((a, b) => a - b);
    const uniqueQueries: number[] = [];
    for (let i = 0; i < sortedQueries.length; i++) {
        const value = sortedQueries[i];
        if (uniqueQueries.length === 0 || uniqueQueries[uniqueQueries.length - 1] !== value) {
            uniqueQueries.push(value);
        }
    }

    const heap = new Heap<[number, number]>((a, b) => a[0] < b[0] || (a[0] === b[0] && a[1] < b[1]));  // [size, right] of started intervals
    const answerFor = new Map<number, number>();   // query value -> answer

    for (let qIndex = 0; qIndex < uniqueQueries.length; qIndex++) {
        const query = uniqueQueries[qIndex];

        // Push every interval that has started (left <= query).
        while (nextInterval < intervals.length && intervals[nextInterval][0] <= query) {
            const left = intervals[nextInterval][0];
            const right = intervals[nextInterval][1];
            const size = right - left + 1;
            heap.push([size, right]);
            nextInterval = nextInterval + 1;

        // Later queries are even bigger, so they stay useless.

            heap.pop();

        answerFor.set(query, heap.size > 0 ? heap.peek()[0] : -1);

    const result: number[] = [];

// ---- helper: a small binary heap (TypeScript has no built-in priority queue) ----
// `less(a, b)` decides which item comes out first. The player doesn't step inside it.
class Heap<T> {
    private items: T[] = [];
    private less: (a: T, b: T) => boolean;

    constructor(less: (a: T, b: T) => boolean) {
        this.less = less;
    }

    get size(): number {
        return this.items.length;
    }

    peek(): T {
        return this.items[0];
    }

    push(x: T): void {
        const a = this.items;
        a.push(x);
        let i = a.length - 1;
        while (i > 0) {
            const parent = (i - 1) >> 1;
            if (!this.less(a[i], a[parent])) {
                break;
            }
            [a[i], a[parent]] = [a[parent], a[i]];
            i = parent;
        }
    }

    pop(): T {
        const a = this.items;
        const top = a[0];
        const last = a.pop()!;
        if (a.length > 0) {
            a[0] = last;
            let i = 0;
            while (true) {
                const l = 2 * i + 1;
                const r = l + 1;
                let m = i;
                if (l < a.length && this.less(a[l], a[m])) {
                    m = l;
                }
                if (r < a.length && this.less(a[r], a[m])) {
                    m = r;
                }
                if (m === i) {
                    break;
                }
                [a[i], a[m]] = [a[m], a[i]];
                i = m;
            }
        }
        return top;
    }
}

From brute force to the pattern: Checking the height at every x coordinate is far too slow for large coordinates. A sweep over sorted edges with a max-heap (lazy removal) gives O(n log n).

Spot it: Sweep left to right over building edges. At each x, the skyline's height is the tallest building that is currently "live", so use a max-heap of live heights. When that maximum changes, record a key point.

Approach:

  1. Make events: (left, −height, right) for starts and (right, 0, 0) for ends. Sorting puts taller starts first at the same x.
  2. Keep a max-heap live of (−height, right), seeded with the ground (0, ∞).
  3. At each event, push the building if it's a start. Then lazily pop tops whose right ≤ x.
  4. If the current max height differs from the last key point's height, append [x, height].
import heapq
from typing import List


class Solution:
    def getSkyline(self, buildings: List[List[int]]) -> List[List[int]]:
        # heapq is a MIN-heap: heapq.heappop(heap) removes the smallest
        # item and heap[0] is the smallest. We need the TALLEST building,
        # so we store heights as NEGATIVE numbers: the tallest building
        # then has the smallest (most negative) value and sits at heap[0].
        # This is the "negative-number max-heap trick".

        # Make two events per building.
        events = []
        for i in range(len(buildings)):
            left = buildings[i][0]
            right = buildings[i][1]
            height = buildings[i][2]
            # Start event: (x, -height, right). At the same x, a taller
            # building has a smaller -height, so it is handled first.
            events.append((left, -height, right))
            # End event: (x, 0, 0). It adds nothing; it just makes us
            # clean up buildings that have ended at this x.
            events.append((right, 0, 0))
        events.sort()

        result = []
        # Live buildings as (-height, right). The ground (height 0)
        # never ends, so the heap is never empty.
        live = []
        heapq.heappush(live, (0, float("inf")))

        for i in range(len(events)):
            event_x = events[i][0]
            negative_height = events[i][1]
            right = events[i][2]

            if negative_height != 0:
                # A building starts here: it becomes live.
                heapq.heappush(live, (negative_height, right))

            # Remove tallest buildings that already ended (right <= event_x).
            # We only need to clean the top, because only the top
            # decides the current height ("lazy deletion").
            while live[0][1] <= event_x:
                heapq.heappop(live)

            # Current skyline height = tallest live building.
            current_height = -live[0][0]

            # Record a key point only if the height changed.
            if len(result) == 0:
                result.append([event_x, current_height])
            elif result[len(result) - 1][1] != current_height:
                result.append([event_x, current_height])
        return result
function getSkyline(buildings: number[][]): number[][] {
    // Make two events per building, sorted by x.
    // Start event: [x, -height, right]. At the same x, a taller building has
    // a smaller -height, so it is handled first.
    // End event: [x, 0, 0]. It adds nothing; it just makes us clean up
    // buildings that have ended at this x.
    const events: [number, number, number][] = [];
    for (let i = 0; i < buildings.length; i++) {
        const left = buildings[i][0];
        const right = buildings[i][1];
        const height = buildings[i][2];
        events.push([left, -height, right]);
        events.push([right, 0, 0]);
    }
    events.sort((a, b) => a[0] - b[0] || a[1] - b[1] || a[2] - b[2]);

    const result: number[][] = [];
    // Live buildings as [height, right], TALLEST on top (a max-heap).
    // The ground (height 0) never ends, so the heap is never empty.
    const live = new Heap<[number, number]>((a, b) => a[0] > b[0] || (a[0] === b[0] && a[1] < b[1]));
    live.push([0, Infinity]);

    for (let i = 0; i < events.length; i++) {
        const eventX = events[i][0];
        const negativeHeight = events[i][1];
        const right = events[i][2];

        if (negativeHeight !== 0) {
            // A building starts here: it becomes live.
            live.push([-negativeHeight, right]);
        }

        // Remove tallest buildings that already ended (right <= eventX).
        // We only need to clean the top, because only the top
        // decides the current height ("lazy deletion").
        while (live.peek()[1] <= eventX) {

// ---- helper: a small binary heap (TypeScript has no built-in priority queue) ----
// `less(a, b)` decides which item comes out first. The player doesn't step inside it.
class Heap<T> {
    private items: T[] = [];
    private less: (a: T, b: T) => boolean;

    constructor(less: (a: T, b: T) => boolean) {
        this.less = less;
    }

    get size(): number {
        return this.items.length;
    }

    peek(): T {
        return this.items[0];
    }

    push(x: T): void {
        const a = this.items;
        a.push(x);
        let i = a.length - 1;
        while (i > 0) {
            const parent = (i - 1) >> 1;
            if (!this.less(a[i], a[parent])) {
                break;
            }
            [a[i], a[parent]] = [a[parent], a[i]];
            i = parent;
        }
    }

    pop(): T {
        const a = this.items;
        const top = a[0];
        const last = a.pop()!;
        if (a.length > 0) {
            a[0] = last;
            let i = 0;
            while (true) {
                const l = 2 * i + 1;
                const r = l + 1;
                let m = i;
                if (l < a.length && this.less(a[l], a[m])) {
                    m = l;
                }
                if (r < a.length && this.less(a[r], a[m])) {
                    m = r;
                }
                if (m === i) {
                    break;
                }
                [a[i], a[m]] = [a[m], a[i]];
                i = m;
            }
        }
        return top;
    }
}
class Solution {
    public List<List<Integer>> getSkyline(int[][] buildings) {
        // Make two events per building, sorted by x.
        // Start event: (x, -height, right). At the same x, a taller building has
        // a smaller -height, so it is handled first.
        // End event: (x, 0, 0). It adds nothing; it just makes us clean up
        // buildings that have ended at this x.
        List<int[]> events = new ArrayList<>();
        for (int[] b : buildings) {
            events.add(new int[] {b[0], -b[2], b[1]});
            events.add(new int[] {b[1], 0, 0});
        }
        events.sort((a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0])
                : a[1] != b[1] ? Integer.compare(a[1], b[1]) : Integer.compare(a[2], b[2]));

        List<List<Integer>> result = new ArrayList<>();
        // Live buildings as (height, right), TALLEST on top (a max-heap).
        // The ground (height 0) never ends, so the heap is never empty.
        PriorityQueue<long[]> live = new PriorityQueue<>((a, b) -> a[0] != b[0] ? Long.compare(b[0], a[0]) : Long.compare(a[1], b[1]));
        live.offer(new long[] {0, Long.MAX_VALUE});

        for (int[] event : events) {
            int eventX = event[0];
            int negativeHeight = event[1];
            int right = event[2];

            if (negativeHeight != 0) {
                // A building starts here: it becomes live.
                live.offer(new long[] {-negativeHeight, right});
            }

            // Remove tallest buildings that already ended (right <= eventX).
            // We only need to clean the top, because only the top
            // decides the current height ("lazy deletion").
            while (live.peek()[1] <= eventX) {
                live.poll();
            }

            // Current skyline height = tallest live building.
            int currentHeight = (int) live.peek()[0];

            // Record a key point only if the height changed.
            if (result.isEmpty() || result.get(result.size() - 1).get(1) != currentHeight) {
                result.add(List.of(eventX, currentHeight));
            }
        }
        return result;
    }
}

What the code is doing, line by line:

  1. The comment at the top explains the max-heap trick. Python's heapq only gives you the smallest item. Storing -height makes the tallest building the smallest number, so it sits at live[0].
  2. Building the events: for each building we read left, right and height by index. A start event is (left, -height, right). An end event is (right, 0, 0). It carries no building; it just tells the sweep to stop at right and tidy up.
  3. events.sort() orders the events left to right. Tuples compare item by item, so at the same x a taller start (more negative) comes first, and starts (negative) come before end markers (0).
  4. live starts with the ground (0, inf). Its height is 0 and it never ends, so live[0] always exists.
  5. In the loop we read the three fields of the event by index. If negative_height != 0, this is a start event, so we push the building into live.
  6. The while loop pops the top building while it has already ended (right <= event_x). Ended buildings deeper in the heap can stay for now; they get removed later if they ever reach the top. That is called lazy deletion.
  7. current_height = -live[0][0] flips the sign back to get the real height of the tallest live building.
  8. Recording: if result is empty, or the last key point has a different height, the outline changed here, so we append [event_x, current_height]. Otherwise the height is unchanged and nothing is recorded.

Hint 1

Store the covered numbers as a sorted list of disjoint intervals.

Hint 2

Adding merges overlapping intervals; removing splits them; a query only needs the interval that starts at or before left.

From brute force to the pattern: Marking every integer is impossible for ranges up to 10⁹. Keeping disjoint intervals means each operation only touches the intervals that overlap the given range.

Spot it: A set of numbers stored as disjoint, sorted intervals: adding merges overlapping intervals, removing splits them, and querying finds the one interval that could contain the range. That's interval merging plus binary search.

Why not another pattern? A boolean array over all numbers is impossible (up to 10⁹). A segment tree with lazy propagation works but is far more code.

Approach:

  1. Store a sorted list of disjoint intervals.
  2. addRange: drop every interval that overlaps or touches [left, right), extend the new range to cover them, insert it.
  3. removeRange: drop overlapping intervals, but keep their parts sticking out on the left or right.
  4. queryRange: binary-search the last interval starting at or before left; covered if it ends at or after right.

    def __init__(self):
        self.intervals = []  # sorted, disjoint [start, end) pairs

  4. removeRange keeps the parts of each overlapping interval that lie outside [left, right).

Problem: For each interval, return the index of the interval with the smallest start ≥ its end (or −1).

Example 2
Input: intervals = [[3,4],[2,3],[1,2]]
Output: [-1,0,1]
Explanation: There is no right interval for [3,4]. The right interval for [2,3] is [3,4] since start0 = 3 is the smallest start that is >= end1 = 3. The right interval for [1,2] is [2,3] since start1 = 2 is the smallest start that is >= end2 = 2.

Constraints: 1 ≤ intervals.length ≤ 2 * 10⁴ · intervals[i].length == 2 · -10⁶ ≤ starti ≤ endi ≤ 10⁶ · The start point of each interval is unique.

Hint 1

For each end, you need the smallest start that is at least that end.

Hint 2

Sort the starts and binary-search.

From brute force to the pattern: All pairs: O(n²); sort + binary search: O(n log n).

Spot it: An intervals question answered by sorting starts and binary search: for each end, find the first start at or after it.

Why not another pattern? Checking all pairs is O(n²).

Approach:

  1. starts = sorted((start, index)).
  2. For each interval: bisect_left(starts, (end, −1)); return that index or −1.
from bisect import bisect_left

class Solution:
    def findRightInterval(self, intervals: List[List[int]]) -> List[int]:
        starts = sorted((s, i) for i, (s, _) in enumerate(intervals))
        result = []
        for _, end in intervals:
            j = bisect_left(starts, (end, -1))  # first start >= end
            result.append(starts[j][1] if j < len(starts) else -1)
        return result
function findRightInterval(intervals: number[][]): number[] {
    // [start, original index], sorted by start
    const starts = intervals.map(([s], i) => [s, i]).sort((a, b) => a[0] - b[0] || a[1] - b[1]);
    const result: number[] = [];
    for (const [, end] of intervals) {
        // first start >= end (binary search)
        let lo = 0;
        let hi = starts.length;
        while (lo < hi) {
            const mid = (lo + hi) >> 1;
            if (starts[mid][0] < end) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        result.push(lo < starts.length ? starts[lo][1] : -1);
    }
    return result;
}
class Solution {
    public int[] findRightInterval(int[][] intervals) {
        int n = intervals.length;
        // (start, original index), sorted by start
        int[][] starts = new int[n][];
        for (int i = 0; i < n; i++) {
            starts[i] = new int[] {intervals[i][0], i};
        }
        Arrays.sort(starts, (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0]) : Integer.compare(a[1], b[1]));
        int[] result = new int[n];
        for (int k = 0; k < n; k++) {
            int end = intervals[k][1];
            // first start >= end (binary search)
            int lo = 0;
            int hi = n;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (starts[mid][0] < end) {
                    lo = mid + 1;
                } else {
                    hi = mid;
                }
            }
            result[k] = lo < n ? starts[lo][1] : -1;
        }
        return result;
    }
}

  1. Starts are unique, so (end, −1) sorts before any (end, i), finding a start equal to end too.
  2. An interval can be its own right interval when start == end.

Hint 1

Brightness changes only at interval ends.

Hint 2

Use a difference map and sweep the sorted points.

From brute force to the pattern: Checking every candidate against every lamp is O(n²); the sweep is O(n log n).

Spot it: Overlapping intervals → a sweep line over a difference map: +1 where a lamp starts, −1 just after it ends; scan the sorted points.

Why not another pattern? Checking each candidate position against every lamp is O(n²).

Approach:

  1. delta[p − r] += 1, delta[p + r + 1] −= 1.
  2. Sweep sorted keys with a running sum; keep the first position with the maximum.
from collections import Counter

class Solution:
    def brightestPosition(self, lights: List[List[int]]) -> int:
        delta = Counter()
        for p, r in lights:
            delta[p - r] += 1  # light starts here
            delta[p + r + 1] -= 1  # and stops after p + r
        best_pos, best = None, -1
        current = 0
        for x in sorted(delta):
            current += delta[x]
            if current > best:
                best, best_pos = current, x  # first (smallest) position with this brightness
        return best_pos
function brightestPosition(lights: number[][]): number {
    const delta = new Map<number, number>();
    for (const [p, r] of lights) {
        delta.set(p - r, (delta.get(p - r) ?? 0) + 1);  // light starts here
        delta.set(p + r + 1, (delta.get(p + r + 1) ?? 0) - 1);  // and stops after p + r
    }
    let bestPos = 0;
    let best = -1;
    let current = 0;
    for (const x of [...delta.keys()].sort((a, b) => a - b)) {
        current += delta.get(x)!;
        if (current > best) {
            best = current;
            bestPos = x;  // first (smallest) position with this brightness
        }
    }
    return bestPos;
}
class Solution {
    public int brightestPosition(int[][] lights) {
        TreeMap<Integer, Integer> delta = new TreeMap<>();  // kept sorted by position
        for (int[] light : lights) {
            int p = light[0], r = light[1];
            delta.merge(p - r, 1, Integer::sum);  // light starts here
            delta.merge(p + r + 1, -1, Integer::sum);  // and stops after p + r
        }
        int bestPos = 0;
        int best = -1;
        int current = 0;
        for (Map.Entry<Integer, Integer> e : delta.entrySet()) {
            current += e.getValue();
            if (current > best) {
                best = current;
                bestPos = e.getKey();  // first (smallest) position with this brightness
            }
        }
        return bestPos;
    }
}
